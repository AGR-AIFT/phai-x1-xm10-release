    XM10 Extension Module SDK v2.5.1¶

    릴리즈 날짜: 2026-07-29 | 대상 HW: Rev 2.0 전용 (Rev 1.1 영향 없음) | KIT H10 FW: v2.3.0+

    ✅ 검증 완료 (2026-07-30) — 릴리즈 직후 "v2.5.1 을 올려도 멈춘다"는 재현 보고가 있어 재조사했으나, 펌웨어가 아니라 디버깅 환경이 원인으로 확인되었습니다 (이전 세션에 남아 있던 중단점 + 구버전 ST-LINK 펌웨어가 디버그 세션 중 인터럽트를 계속 막고 있었음). v2.5.1 펌웨어는 정상 동작이 확인되었습니다. 비슷한 상황을 겪는다면 아래 "디버깅 시 주의" 섹션을 먼저 확인하세요.

    한눈에 보기¶

    Rev 2.0 보드가 부팅 도중 멈추던 문제를 고친 긴급 수정 릴리즈입니다. 기능 변경은 없습니다.

    • 증상 — 보드에 전원을 넣어도 LED 가 반응하지 않고, PC 에 COM 포트(USB 시리얼)가 나타나지 않습니다. 펌웨어가 부팅 중간에 멈춰 있는 상태입니다.
    • 해당 버전 — v2.4.1 · v2.5.0 의 Rev 2.0 펌웨어. v2.4.0 이하는 해당 없습니다.
    • Rev 1.1 은 영향 없습니다 — 원인이 된 코드가 Rev 1.1 에는 애초에 없습니다. Rev 1.1 을 쓰신다면 그대로 사용하시면 됩니다.
    • 조치 — Rev 2.0 사용자는 Rev2.0.zip 을 받아 다시 빌드·업로드해 주세요.
    • 부트로더 (선택) — 안정성을 개선한 최신 부트로더 빌드(2026-07-30) 를 함께 첨부했습니다. 기존 부트로더도 정상 동작하므로 필수는 아니며, 여유가 있을 때 업데이트하면 좋습니다.

    무슨 일이 있었나요? (쉽게)¶

    보드 안에는 1 초에 1000 번 똑딱이는 시계가 있습니다. 펌웨어는 "0.01 초만 기다렸다 하자" 같은 일을 할 때 이 시계를 봅니다.

    그런데 부팅 아주 초반에, 잠깐 "지금은 방해하지 마" 하고 인터럽트를 막아두는 구간이 있었습니다. 원래는 그 구간이 끝나면 바로 풀려야 하는데, 아직 운영체제(FreeRTOS)가 시작되기 전이라 푸는 쪽 코드가 동작하지 않았습니다. 그 바람에 방해 금지가 계속 걸린 채로 남았고, 시계가 똑딱이지 못했습니다.

    그다음이 문제였습니다. 부팅 과정에서 처음으로 "잠깐 기다려" 를 하는 곳이 USB 초기화인데, 시계가 멈춰 있으니 기다림이 영원히 끝나지 않습니다. 그래서 보드는 USB 초기화에서 그대로 멈춰 섭니다.

    USB 가 고장 난 것이 아닙니다. USB 는 그저 시계가 멈춘 걸 처음 알아챈 자리였을 뿐입니다.

    이번 릴리즈는 그 "방해 금지"를 끝나면 확실히 풀도록 고쳤습니다. 혹시 다른 곳에서 같은 일이 생기더라도 부팅 시작 시점에 한 번 더 풀어주는 안전장치도 함께 넣었습니다.

    내 보드가 해당되나요?¶

    확인 해당 여부
    보드에 RJ45 Ethernet 포트가 있다 (= Rev 2.0) + 펌웨어가 v2.4.1 또는 v2.5.0 해당 — v2.5.1 로 업데이트
    보드에 RJ45 포트가 없다 (= Rev 1.1) 해당 없음 — 그대로 사용
    Rev 2.0 인데 펌웨어가 v2.4.0 이하 해당 없음 (다만 최신 사용 권장)

    부팅이 잘 되고 PC 에 COM 포트가 보인다면 해당되지 않습니다.

    업데이트 방법¶

    1. 아래 Rev2.0.zip 을 받아 압축을 풉니다 (한글·공백 없는 경로에).
    2. STM32CubeIDE 로 열어 빌드합니다.
    3. PhAI Studio USB 업로드로 보드에 올립니다. 부트로더는 이미 설치되어 있으므로 재설치가 필요 없습니다.

    보드가 이미 멈춰 있어 PhAI Studio 로 연결되지 않는다면, SWD(ST-Link) 로 한 번 직접 플래시하시면 됩니다.

    디버깅 시 주의 — "업데이트했는데도 멈춰 보여요"¶

    v2.5.1 을 올렸는데도 같은 곳에서 멈춘 것처럼 보인다면, 보드나 펌웨어가 아니라 디버깅 환경 때문일 수 있습니다. 실제로 릴리즈 직후 접수된 재현 보고가, 조사 결과 아래 두 가지가 겹친 것으로 확인되었습니다.

    1. ST-LINK 펌웨어를 최신으로 업그레이드하세요 — STM32CubeIDE 메뉴 Help → ST-LINK Upgrade. 구버전 ST-LINK 펌웨어는 디버그 세션 중 인터럽트를 계속 막아 둘 수 있어, 멀쩡한 펌웨어도 1 ms 시계(틱)가 멈춘 것처럼 보이게 만듭니다.
    2. 이전 세션의 중단점(breakpoint)을 모두 지우세요 — Run → Remove All Breakpoints.
    3. 그래도 이상하면 모든 케이블을 뽑고 보드 전원을 완전히 껐다 켠 뒤, 디버거 없이 전원만 연결해 보세요. LED 가 켜지고 PC 에 COM 포트가 나타나면 펌웨어는 정상입니다. (디버거가 남긴 인터럽트 마스크는 전원을 완전히 끊어야만 지워집니다.)

    다운로드¶

    파일 대상 보드
    Rev2.0.zip XM10 Rev 2.0 (RJ45 Ethernet 포트 있는 최신 보드) — v2.5.1
    Rev1.1.zip XM10 Rev 1.1 (초기 개발용 보드) — v2.5.0 과 동일 (변경 없음)

    이번 수정은 Rev 2.0 에만 해당하므로, Rev1.1.zip 은 v2.5.0 과 같은 파일입니다. Rev 1.1 을 쓰신다면 이미 받으신 것을 계속 쓰셔도 됩니다.

    Release 첨부 파일¶

    파일 용도
    AGR_Bootloader.bin XM10 부트로더 — 2026-07-30 최신 빌드 (SWD 로 1 회 설치. 이후 FW 는 PhAI Studio USB 업로드)
    SUIT_H10_Binary_20260716.zip KIT H10 (CM · MD · ESP32) 펌웨어 — USB 스틱에 넣어 업데이트
    SUIT_ContentsFiles.zip KIT H10 컨텐츠 파일 (모션 · 사운드 등) — USB 스틱에 함께

    부트로더가 최신 빌드로 교체되었습니다 (2026-07-30) — 앱으로 넘어가기 직전에 남아 있을 수 있는 시스템 인터럽트 흔적을 정리하는 안정성 개선이 들어갔습니다. 기존 부트로더로도 동작에 큰 문제는 없으므로 필수는 아니지만, SWD 로 플래시할 기회가 있다면 최신으로 업데이트하는 것을 권장합니다. KIT H10 펌웨어 · 컨텐츠 파일은 이전 릴리즈와 동일합니다 — 이미 업데이트하셨다면 추가 작업이 없습니다. 설치 방법은 부트로더 업로드 · KIT H10 펌웨어 문서를 참고하세요.
