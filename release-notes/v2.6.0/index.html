    XM10 Extension Module SDK v2.6.0¶

    릴리즈 날짜: 2026-08-20 | 대상 HW: Rev 1.1 · Rev 2.0 공통 | KIT H10 FW: v2.3.0+

    한눈에 보기¶

    안전성 릴리즈입니다. 새 기능을 늘리기보다, "끌 때 확실히 꺼지고, 멈추면 스스로 되살아나는" 쪽을 손봤습니다. 전체 코드를 처음부터 다시 훑어보는 점검(전수 리뷰)에서 나온 결과를 반영했습니다.

    • 제어를 끄면 확실히 꺼집니다 — 예전에는 MONITOR 로 돌아가도 마지막에 보낸 토크가 H10 쪽에 그대로 남아 있을 수 있었습니다. 이제는 토크를 부드럽게 0 까지 내린 뒤, 0 을 확실히 보내고, 그 다음에 출력을 끕니다.
    • 펌웨어가 멈춰도 보드가 스스로 재시작합니다 — 하드웨어 워치독(약 8 초)을 넣었습니다. 무한 재부팅으로 빠지지 않도록 부팅 실패 처리도 함께 고쳤습니다.
    • 예제 12 개가 더 안전해졌습니다 — 시작할 때 갑자기 튀지 않도록(소프트스타트), 버튼을 눌렀을 때 턱턱 치지 않도록(미분킥 제거), 센서가 끊기면 멈추도록 손봤습니다.
    • forwardVelocity 값이 바로잡혔습니다 — 60 배 크게 나오던 버그입니다. 이 값을 쓰셨다면 아래 호환성 안내를 꼭 읽어주세요.
    • 외부 장비와 시점 맞추기(Ext_Sync) — 외부 sync box 의 TTL 신호를 받아 "지금 저장 중인가"를 데이터에 같이 실어 보냅니다.

    Rev 1.1 사용자에게: 이번 릴리즈는 v2.5.0 이후 Rev 1.1 에 들어가는 첫 업데이트입니다(v2.5.1 은 Rev 2.0 전용이었습니다). 위 내용이 전부 Rev 1.1 에도 적용됩니다.

    1. 제어를 끄면 확실히 꺼집니다¶

    무엇이 문제였나 (쉽게)¶

    XM10 은 H10 에게 "이만큼 도와줘" 하고 토크 명령을 계속 보내는 구조입니다. 그런데 H10 은 새 명령이 안 오면 마지막에 받은 명령을 계속 유지합니다(신호가 끊겨도 로봇이 갑자기 멈추지 않도록 하는 안전 장치입니다).

    문제는 여기서 생겼습니다. XM_SetControlMode(XM_CTRL_MONITOR) 로 제어를 끄면, XM10 은 그 순간부터 전송을 멈춰버렸습니다. 그러면 H10 입장에서는 "마지막 명령(0 이 아닌 토크)이 계속 유효"한 상태가 됩니다. 끈 줄 알았는데 토크가 남아 있는 것이죠.

    어떻게 고쳤나¶

    이제 MONITOR 로 돌아갈 때 3 단계를 거칩니다.

    1. 부드럽게 내리기 — 마지막 토크에서 0 까지 지수적으로 감쇠시키며 계속 전송합니다(시정수 0.1 초).
    2. 0 확정 보내기 — 0 토크를 여러 번 확실히 보냅니다(프레임 하나가 유실돼도 안전하도록).
    3. 벡터 해제 — P/I 벡터를 쓰고 있었다면 해제 명령까지 보낸 뒤, 그때서야 출력을 끕니다.

    전체 소요 시간은 보통 0.3 ~ 0.6 초입니다.

    즉시 멈춰야 할 때¶

    부드럽게 내릴 여유조차 없다면 XM_EmergencyDisengage() 를 부르세요. 감쇠 단계를 건너뛰고 곧바로 0 을 확정 전송합니다.

    if (something_is_wrong) {
    XM_EmergencyDisengage();   // 램프 생략, 즉시 0
}

    지금 어느 상태인지 보기¶

    XM_SetControlMode() 는 "요청"이고, 실제 적용 상태는 위 3 단계 때문에 잠깐 다를 수 있습니다. 실제 상태는 새 함수로 확인합니다.

    XmAppliedMode_t m = XM_GetAppliedControlMode();
// XM_MODE_APPLIED_CONTROL     — 제어 출력 중
// XM_MODE_APPLIED_MONITOR     — 출력 차단됨
// XM_MODE_APPLIED_TRANSITION  — 전환 중 (이 동안 사용자 토크 명령은 반영되지 않음)

    MONITOR 는 이제 완전한 차단입니다. MONITOR 상태에서는 토크든 벡터든 어떤 제어 명령도 나가지 않습니다. 알고리즘을 돌려보며 값만 관찰할 때 안심하고 쓰세요.

    2. 펌웨어가 멈춰도 보드가 스스로 재시작합니다¶

    워치독(watchdog) 은 "일정 시간마다 살아 있다고 도장을 찍지 않으면 강제로 재부팅시키는" 장치입니다. XM10 에 약 8 초 짜리 하드웨어 워치독(IWDG)을 넣었습니다. 도장은 Control_Loop 가 도는 태스크가 1 kHz 로 찍습니다.

    함께 고친 것:

    • 무한 재부팅 방지 — 예전에는 초기화 도중 실패하면 재부팅 → 또 실패 → 또 재부팅을 반복할 수 있었습니다. 이제 초기화 단계의 실패는 그 자리에서 멈춰서(halt) 원인을 볼 수 있게 하고, 정상 동작 중에 멈춘 경우에만 워치독이 재시작시킵니다.
    • 부팅 흔적 기록 — 어디까지 부팅했는지, 왜 리셋됐는지가 메모리에 남습니다. 문제 상황을 재현하지 않고도 원인을 좁힐 수 있습니다.

    ⚠️ 워치독은 비상 정지 장치가 아닙니다. 코드가 멈추지 않은 채 잘못된 토크를 계속 내보내는 경우에는 워치독이 아예 동작하지 않습니다(펌웨어 입장에서는 정상 실행 중이니까요). 착용 실험에서는 착용 안전 수칙대로 사람이 직접 정지시키는 것이 여전히 1 차 안전망입니다.

    ⚠️ 사용자 task 를 만든다면: 여러분의 task 가 Control_Loop 보다 높은 우선순위로 8 초 이상 CPU 를 붙들면 보드가 리셋됩니다. 주기적으로 XM_Task_Sleep() 으로 양보하세요. (Task 생성 가이드 §4)

    3. 예제가 더 안전해졌습니다¶

    12 개 예제를 손봤습니다. 예제 번호와 배우는 내용은 그대로이고, 안전 장치만 추가·정리했습니다.

    무엇 어느 예제 왜
    진입 소프트스타트 / 기울기 제한 Ex.14 · 21 · 27 · 30 · 33 보조를 켜는 순간 토크가 0 에서 목표로 튀어 오르며 "턱" 하는 충격을 없앰
    미분킥 제거 Ex.14 목표값이 계단처럼 바뀔 때 D 항이 순간적으로 폭발하던 현상. 미분을 오차가 아닌 측정값에 걸어 원천 제거
    정지 스위치 NC 처리 · 출력 클램프 · 정지 램프 · 센서 끊김 타임아웃 Ex.06 · 13 · 17 · 26 · 32 스위치 배선이 끊겨도 "정지"로 읽히도록, 값이 튀어도 한계를 넘지 않도록
    모드 전환 정합 · 호밍 실패 시 안전 정지 Ex.11 · 12 · 15 · 35 · 36 호밍이 안 끝났는데 제어로 들어가는 경로 차단
    이중 단위 변환 제거 Ex.11 · 12 · 15 · 35 · 36 전류(A)를 토크(Nm)로 두 번 변환하던 곳 정리

    벤치(로봇을 착용하지 않은 상태) 안내 추가¶

    Ex.15 · 21 · 30 · 33 은 원래 사람이 착용한 상태를 전제로 게인이 잡혀 있습니다. 착용하지 않고 다리만 매달린 상태에서 돌리면 관성이 훨씬 작아 진동하거나 발산합니다 — 예제가 고장 난 게 아닙니다.

    그래서 각 예제 파일 맨 위에 벤치용 파라미터 안내 주석을 넣었습니다. 링크 단독 질량·무게중심 값(0.184 kg / 0.1264 m)으로 바꿔 넣으면 벤치에서도 안정적으로 관찰할 수 있습니다.

    4. forwardVelocity 값이 바로잡혔습니다 ⚠️¶

    XM.status.h10.forwardVelocity 가 실제보다 60 배 크게 나오고 있었습니다. 단위 변환 과정에서 분당(per minute) → 초당(per second) 나눗셈이 빠져 있었습니다.

    • 이 값을 화면에 보기만 했다면 — 이제 정상적인 크기로 보입니다. 별도 조치 없습니다.
    • 이 값을 제어에 썼다면 — 60 배를 상쇄하려고 게인을 아주 작게 잡아두셨을 수 있습니다. 게인을 다시 잡아주세요.
    • 예전에 모은 데이터가 있다면 — 그 데이터의 forwardVelocity 는 60 배 값입니다. 새 데이터와 섞어 쓰지 마세요.

    5. 외부 장비와 시점 맞추기 (Ext_Sync)¶

    외부 계측 장비(sync box)의 TTL 신호를 XM10 의 확장 입력 DIO8 로 받아, 실시간 데이터에 함께 실어 보냅니다. 이제 PhAI Studio 에서 "언제부터 언제까지가 저장 구간인지"를 XM10 데이터와 같은 타임라인 위에서 볼 수 있습니다.

    Total Data 에 3 개 채널이 추가되었습니다.

    채널 뜻
    sync_save_active 1 = 저장 중 — 이것만 보면 됩니다
    sync_din_level 지금 핀의 전기 레벨 (진단용)
    sync_din_edge_count 신호가 바뀐 총 횟수 (누락 교차 확인용)

    극성을 신경 쓰지 않아도 됩니다. sync box 는 버튼으로 출력 극성이 뒤집히기 때문에, "저장 시작 = HIGH" 인지 "= LOW" 인지가 그날그날 달라질 수 있습니다. XM10 은 부팅 직후 읽은 레벨을 '쉬는 상태'로 기억해두고, 그와 달라지면 저장 중으로 판정합니다. 어느 극성이든 알아서 맞춥니다.

    연결 순서만 지켜주세요. ① sync box 를 저장 중이 아닌 상태(주황 LED 꺼짐)로 두고 → ② XM10 전원을 켜고 → ③ 이후에는 sync box 의 버튼을 누르지 마세요(버튼도 전기적으로는 저장 신호와 똑같은 파형이라 구분할 수 없습니다). 저장은 태블릿 앱에서만 조작합니다.

    배선: sync box TTL 출력(0/3.3 V) → XM10 확장 커넥터 DIO8, GND 공통.

    6. 그 밖에 (Rev 2.0 전용)¶

    • USB 시리얼 연결이 더 튼튼해졌습니다 — 케이블을 뽑았다 꽂거나 PC 를 바꿀 때 전송이 엉키던 문제, 역할 전환 중 잘못된 상태로 들어가던 문제를 고쳤습니다.
    • 진단 정보 확장 — 통신 오류 누적 횟수, 부팅 단계별 실패 표시, 태스크 스택 여유 등을 볼 수 있습니다.
    • 펌웨어 빌드에 Git 커밋 정보가 들어갑니다 — 지금 보드에 올라간 게 정확히 어느 버전인지 확인할 수 있습니다.

    새로 생긴 API¶

    API 용도
    XM_EmergencyDisengage() 램프다운 생략, 즉시 토크 0 확정
    XM_GetAppliedControlMode() 요청이 아닌 실제 적용 제어 모드 조회
    xm_api_safety.h (헤더만 포함) 공통 안전 헬퍼 — XM_SafeTorque_*(한계 + 기울기 제한), XM_SafeAssistLevel(), XM_SafeIsFresh()(센서 신선도)

    xm_api_safety.h 는 xm_api.h 에 이미 포함되어 있으므로 따로 #include 하지 않아도 됩니다.

    static XmSafeTorque_t s_safe;

void Control_Setup(void) {
    /* 한계 2.5 Nm | 0→한계까지 최소 500 ms (기울기 제한, 0 이면 제한 없음)
     * | 진입 소프트스타트 500 ms */
    XM_SafeTorque_Init(&s_safe, 2.5f, 500U, XM_SAFETY_DEFAULT_RAMP_MS);
}

void Control_Loop(void) {
    /* 유한값 확인 → 한계 클램프 → 소프트스타트 → 기울기 제한을 한 번에 */
    float t = XM_SafeTorque_Step(&s_safe, my_desired_torque);
    XM_SetAssistTorqueRH(t);
}

    제어를 껐다가 다시 켤 때는 XM_SafeTorque_Reset(&s_safe) 를 불러 소프트스타트를 다시 시작시키세요. XM_SafeTorque_Step() 은 Control_Loop 에서 매 tick 정확히 한 번 호출해야 시간 계산이 맞습니다.

    파일 대상 보드

    Rev1.1.zip XM10 Rev 1.1 (초기 개발용 보드)

    본인 보드 리비전과 같은 ZIP 을 받아주세요. RJ45 Ethernet 포트가 있으면 Rev 2.0, 없으면 Rev 1.1 입니다.

    Release 첨부 파일¶

    파일 용도 이번에 바뀌었나
    AGR_Bootloader.bin XM10 부트로더 (SWD 로 설치) 🔄 갱신됨 — 재설치 권장
    SUIT_H10_Binary_20260716.zip KIT H10 (CM · MD · ESP32) 펌웨어 이전과 동일
    SUIT_ContentsFiles.zip KIT H10 컨텐츠 파일 (모션 · 사운드) 이전과 동일

    부트로더가 갱신되었습니다. 두 가지를 고쳤습니다.

    1. 설정 영역이 손상돼도 스스로 복구 — 부트로더가 쓰는 설정 영역이 (전원 이상 등으로) 깨지면 읽는 순간 오류가 나면서 보드가 부팅되지 않을 수 있었습니다. 이제 그 상황을 감지해 설정을 초기화하고 정상 부팅합니다.
    2. 앱으로 넘어갈 때 잔재 정리 — 부트로더에서 사용자 펌웨어로 넘어가는 순간, 처리되지 않고 남아 있던 시스템 인터럽트를 정리합니다.

    SWD 로 한 번 다시 설치해 주세요. 설치 방법은 부트로더 업로드 문서를 참고하세요. KIT H10 펌웨어·컨텐츠 파일은 이전과 동일하므로 이미 설치하셨다면 추가 작업이 없습니다.

    준비물 안내¶

    빌드 마무리 단계(업로드용 .bin 생성)가 Python 을 사용합니다. 아직 설치하지 않았다면 개발 환경 구축 안내대로 Python 3.10+ 를 설치해 주세요 (PATH 등록 필수).

    호환성 안내¶

    항목 영향
    사용자 코드 (Control_Setup / Control_Loop) 재빌드만 하면 됩니다 — 삭제된 함수 없음. XM_CTRL_TORQUE 라는 옛 이름도 그대로 씁니다
    XM_SetControlMode(XM_CTRL_MONITOR) 동작 변경 — 즉시 차단이 아니라 0.3~0.6 초 램프다운 후 차단. 그 사이 사용자 토크 명령은 무시됩니다. 즉시 정지는 XM_EmergencyDisengage()
    MONITOR 모드 동작 변경 — 이제 토크·벡터 모두 완전 차단
    XM.status.h10.forwardVelocity 값 변경 (60 배 정정) — 이 값을 쓰던 코드는 게인 재조정 필요. 예전 데이터와 섞어 쓰지 말 것
    사용자 task 제약 추가 — 8 초 이상 CPU 독점 시 워치독 리셋
    Total Data 패킷 크기 그대로 (365 B) — Ext_Sync 3 채널은 기존 예약(reserved) 영역에 들어갔습니다. 뒤쪽 채널들의 위치가 바뀌지 않아 기존 수신 프로그램은 수정 없이 그대로 동작합니다
    PhAI Studio 그대로 동작 — 새 3 채널은 보이면 활용, 안 보여도 무방
    KIT H10 펌웨어·컨텐츠 파일 이전과 동일 — 추가 업데이트 불필요
    부트로더 갱신됨 — SWD 재설치 권장
    예제 개수 변동 없음 (Rev 2.0 45 개 / Rev 1.1 42 개)
