# CANopen 드라이브 PC 시뮬레이터 (Ex.46 · Ex.47 의 상대)

XM10 예제 [Ex.46 CANopen Drive](../../examples/46_CANopen_Drive/) · [Ex.47 CANopen Drive PDO](../../examples/47_CANopen_Drive_PDO/) 는 이 시뮬레이터가 상대입니다. 실제 모터와 드라이버 없이, PC 에서 CANopen 속도 모드 드라이브를 흉내 냅니다.

> 🧰 **필요한 것: 클래식 CAN(1 Mbit/s)을 지원하는 USB 어댑터 + Python 3.9 이상 + python-can**

---

## 준비

1. `pip install python-can`
2. 어댑터 드라이버를 설치합니다(python-can 이 지원하는 어댑터 — PEAK · Kvaser · Vector 등).
3. 배선 — 어댑터의 CAN_H · CAN_L · GND 를 XM10 CAN-FD #2 포트의 같은 이름에 연결합니다. 버스 양 끝에 120 Ω 이 있어야 합니다. XM10 보드에는 이미 있으므로 어댑터 쪽 끝에 하나를 둡니다(어댑터의 종단 스위치 등).
4. XM10 에 Ex.46 또는 Ex.47 을 올립니다. 두 예제는 포트를 클래식 CAN 으로 정합니다 — 이 포트에 CAN-FD 장치를 함께 연결하지 마세요.

## 실행

```bash
python cia402_drive_sim.py --interface pcan --channel PCAN_USBBUS1
```

| 옵션 | 기본 | 뜻 |
|------|------|------|
| `--interface` · `--channel` | (꼭 줌) | python-can 의 어댑터 이름과 채널 — 예: `pcan` · `PCAN_USBBUS1`, `kvaser` · `0` |
| `--node` | `1` | 노드 ID — XM10 예제의 `EX46_NODE_ID` · `EX47_NODE_ID` 와 같게 |
| `--bitrate` | `1000000` | 클래식 CAN 속도 — XM10 의 `XM_CanClassicBitTiming` 과 같게 |
| `--f-clock-mhz` | `8` | 어댑터의 클래식 CAN 클럭(PEAK 는 8). 샘플 포인트 87.5 % 로 계산해 넣습니다 |
| `--timing none` | — | 어댑터 설정을 그대로 씁니다(밖에서 속도를 정하는 어댑터) |
| `--hb-ms` | `0` | 켜질 때의 하트비트 송신 주기(0 = 끔 — XM10 이 설정할 때 켭니다) |
| `--accel` | `2000` | 프로파일 속도의 가속 한도(단위/s) |
| `--verbose` | — | SDO 쓰기와 중단을 모두 보여 줍니다 |

어댑터 없이 이 PC 안에서만 돌려 보려면 `--interface virtual --channel demo` 를 씁니다(XM10 과는 연결되지 않습니다).

## Ex.46 · Ex.47 과 함께 해 보기

아래는 코드가 의도한 흐름입니다. 보드에서는 아직 확인하지 못했습니다. (보드 확인 전) <!-- board-check -->

1. 시뮬레이터를 켭니다 → 화면에 `부팅 알림 — PRE_OPERATIONAL`
2. XM10 의 버튼 1 → XM10 이 통신 재설정 · 설정을 합니다 → 화면에 `NMT 통신 재설정` · `하트비트 소비 설정` · `하트비트 소비 — 노드 0x7F 감시 시작`, 이어서 `NMT … → OPERATIONAL` · `드라이브 … → OPERATION_ENABLED`
3. `xm10` 도구의 `0xF0` 탭 → 목표 속도 · 실제 속도 · 상태 단어
4. 버튼 1 → 정지
5. **통신 이상 해 보기** — 동작 중에 XM10 의 CAN 선을 뽑으면 0.3 초 뒤 화면에 `하트비트 소비 시간 초과` · `고장 0x8130` 이 나오고 드라이브가 멈춥니다. 다시 연결해도 XM10 은 스스로 다시 움직이지 않습니다(버튼 1 로 처음부터).

## 흉내 내는 것

| 객체 | 뜻 |
|------|------|
| `0x1000` | 장치 종류 `0x00020192`(CiA 402 드라이브) |
| `0x1006` | 통신 주기(µs) — 저장만 합니다 |
| `0x1016:01` | 하트비트 소비 — (기다릴 노드 << 16) · 시간 ms |
| `0x1017` | 하트비트 송신 주기 ms |
| `0x1400` · `0x1600` | RPDO1 — 통신 파라미터 · 매핑(제어 단어 `0x6040` · 목표 속도 `0x60FF` · 동작 모드 `0x6060`) |
| `0x1800` · `0x1A00` | TPDO1 — 통신 파라미터 · 매핑(상태 단어 `0x6041` · 실제 속도 `0x606C` · 고장 코드 `0x603F` · `0x6061`) |
| `0x2F00` | **시뮬레이터 표시** — `"XSIM"` (Ex.46 · 47 은 이 값이 아니면 켜지 않고 멈춥니다) |
| `0x2F01` | **하트비트 소비 상태** — 0 미설정 · 1 첫 하트비트 전 · 2 감시 중 |
| `0x603F` · `0x6040` · `0x6041` | 고장 코드 · 제어 단어 · 상태 단어(CiA 402 상태 기계) |
| `0x6060` · `0x6061` | 동작 모드 — 3 프로파일 속도 · 9 주기 동기 속도 |
| `0x606C` · `0x60FF` | 실제 속도 · 목표 속도 |

- **SDO** — 4 바이트 이하 빠른 전송만 받습니다(분할 전송은 중단 코드 `0x05040001`). STOPPED 에서는 답하지 않습니다.
- **NMT** — 통신 재설정은 통신 설정(`0x1000` ~ `0x1FFF`)을 기본값으로 돌리고, 노드 재설정은 모두 돌립니다. 둘 다 부팅 알림을 다시 보냅니다.
- **하트비트 소비** — 설정 뒤 첫 하트비트를 받아야 감시를 시작합니다. 시간이 넘으면 움직일 수 있는 상태에서는 고장(`0x8130`)으로 들어가 비상 메시지를 보내고 멈추며, OPERATIONAL 이면 PRE_OPERATIONAL 로 갑니다.
- **PDO** — 매핑은 PDO 를 끄고(COB-ID bit 31) 개수를 0 으로 만든 뒤에만 바꿀 수 있습니다. 어기면 중단 코드로 답합니다(`0x08000022` 등). 동기 형식(1 ~ 240)은 SYNC 에서 받아 둔 RPDO 를 적용하고 TPDO 를 냅니다.
- **고장 해제** — 제어 단어 bit 7 이 0 에서 1 로 바뀌는 순간입니다(`0x00` → `0x80`).

## 실제 드라이버와 다른 점

- 모터 · 전류 · 위치가 없습니다. 속도는 계산으로만 움직입니다.
- 통신 상실 반응(고장 · PRE_OPERATIONAL)은 이 시뮬레이터가 정한 것입니다. 실제 드라이버는 설명서로 확인하고 정하세요.
- PDO 는 RPDO1 · TPDO1 만 있습니다.
- `0x2F00` · `0x2F01` 은 이 시뮬레이터에만 있습니다. 실제 드라이버로 바꿀 때는 Ex.46 · 47 의 머리말을 먼저 읽으세요.

## 흔한 증상

| 증상 | 원인 | 확인 |
|------|------|------|
| 화면에 아무 일도 없음 | 속도가 다름 · 종단 저항 없음 · 어댑터 채널이 다름 | `--bitrate` · `--f-clock-mhz` · 배선 |
| XM10 이 '장치 없음' 으로 멈춤 | 노드 ID 가 다름 | `--node` 와 예제의 노드 ID |
| XM10 이 '시뮬레이터가 아님' 으로 멈춤 | 다른 장치가 같은 노드 ID 로 답함 | 버스에 이 시뮬레이터만 두기 |
| SDO 오류로 멈춤 | 중단 코드 | `--verbose` 로 어떤 객체에서 멈췄는지 |
