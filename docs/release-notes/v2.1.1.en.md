- **AGR_BOOT V2 bootloader** introduced for the first time — supports wireless firmware updates via USB FTP
- **Dual HW revision SDK shipped in a single release** — Rev1.1 and Rev2.0 SDKs bundled together
- **44 examples** — a complete learning path from beginner to advanced control (Impedance, CPG, ILC, MRAC, DOB, and more)
- **Enhanced PhAI Studio integration** — automatic Total Data Packet streaming + User Custom channels
- **xm_api_freertos** added — background task API (FreeRTOS wrapper)
- **Full debugging support for libXM_Lib.a** — built with `-Og -g3` and linked with `--whole-archive`

## Full changelog from v2.0.1

### New features

#### AGR_BOOT V2 bootloader (new)
- Wireless firmware updates via USB CDC FTP protocol
- Automatic backup and rollback — restores the previous version after 3 consecutive boot failures
- CRC-32 firmware integrity verification
- **Single bootloader binary** for both Rev1.1 and Rev2.0 (HW GPIO auto-detection)
- Detailed guide: [docs/bootloader/README.md](../bootloader/README.md)

#### Dual HW revision SDK
- `XM10_SDK/Rev1.1/` — for PCB Rev1.1 only (CAN-FD only)
- `XM10_SDK/Rev2.0/` — for PCB Rev2.0 only (CAN-FD + Ethernet + PSRAM + RTC)
- Each SDK is a **self-contained** STM32CubeIDE project — ready to build immediately after import

#### xm_api_freertos — background task API (new)
- `XM_CreateBackgroundTask()` — runs heavy computation in a dedicated task without blocking UserTask (1 kHz)
- Priority `osPriorityNormal` (24) — lower than UserTask (54), so the control loop is unaffected
- Do **not** call control APIs such as `XM_SetAssistTorque` from a background task — share data via `volatile` variables instead

#### Post-build automation pipeline
- Runs automatically on every STM32CubeIDE build:
  - `size_report.py` → `version_generator.py` → `patch_fw_info.py` → `fw_packager.py`
- Final output: `XM10_X_X_X_X.bin` (packaged binary for PhAI Studio FTP upload)
- `boot_fw_info.c` compiled directly in the SDK — placed in the `.fw_header` section to prevent linker garbage collection

#### Major example expansion (20 → 44 examples)
- **Physical AI torque control series** (Ex.20–33): Impedance, Gravity Compensation, CPG, Gait Phase Adaptive, Virtual Constraint, Stance Stiffness, ILC, MRAC, Admittance, Bilateral, FF/FB Hybrid, Friction DOB, GRF Gait Intent, Kinesthetic Teaching
- **MSC logging series** (Ex.10–10c): Basic → Custom Struct → Advanced (Rolling, Markers)
- **Gait analysis logging** (Ex.34): Automatic H10 gait data collection + Python decoder
- **Ex.35 MultiLayer Transparent Control** — multi-layer transparent control (new)
- **Ex.36 OnDevice Kinesthetic Learning** — on-device motion learning (new)

#### Enhanced PhAI Studio integration
- **Total Data Packet** (Module ID 0x20, 365 B): automatically streamed by the system at 1 kHz
- **User Custom channels** (Module ID 0xF0–0xFE): `XM_SetUsbCustomMeta()` + `XM_SendUsbDataWithId()`
- **Auto-Stream**: streaming starts automatically on USB connection (legacy "AGRB MON START" command no longer needed)

### Improvements

#### AGR_MW / IOIF submodule updates
- **AGR_MW**: OD Discovery (name/unit lookup), SDO non-expedited Upload (data larger than 4 bytes), `PDO_MAP_MAX_ENTRIES` config separated
- **IOIF**: TIM PWM/OC interrupt support, `SetCallback` runtime callback injection, ISR-safe `SetOCMode` / `GenerateUpdate`

#### Data Map Code-Gen
- `xm_total_data.yaml` → `xm_total_data_packet.h` auto-generated
- Independent CAN-FD Ch1/Ch2 diagnostics (TEC / REC / LEC / BusStatus / FIFO)
- `timestamp_ms` renamed to `xm_loop_count` (UserTask execution counter — detects blocking)

#### Build system
- **`--whole-archive` linker setting**: guarantees HAL `__weak` callback overrides (pattern carried over from v2.0.1)
  - `.cproject`: add `-Wl,--whole-archive libXM_Lib.a -Wl,--no-whole-archive` to Other flags
  - `CMakeLists.txt`: same wrapping applied
- **libXM_Lib.a build**: `-Og -g3` (debug optimization + maximum debug symbols)
  - Live Expressions and breakpoints work correctly (Rev1.1: 66 MB, Rev2.0: 88 MB)
  - No effect on the Flash binary size (debug symbols are in the `.elf` only)
- `CMakeLists.txt` cleanup: removed dead paths, fixed capitalization (`Xsens` → `XSENS`)
- Added `ExitRun0Mode()` function (CubeMX 6.13+ startup compatibility)

#### Example tuning
- **Ex.11 Passive Mode / Ex.12 Active Assist Mode**: homing acceleration 4 → 2 deg/s², IVectorKpKd (6, 1) → (6, 6), PVectorReset added

### KIT H10 FW changes (based on v2.3.0)

Key fixes in the H10 CM firmware:

- **BLE CM mode synchronization**: CM internal state is now updated immediately when the mode is changed from the BLE app
- **XM ↔ CM CAN-FD SYNC**: synchronization protocol improved
- **postProcessingCnt PDO added**: gait analysis post-processing counter is now exposed externally
- **Left IMU data fix**: corrected a data mapping error for the left IMU

> For H10 FW update instructions, see: [docs/kit-h10-firmware/README.md](../kit-h10-firmware/README.md)

### Removed

- `BuffMngr` module removed (dropped from AGR_MW)
- Root copy of `user_app.c` removed (managed exclusively under `XM_Apps/User_Algorithm/`)

## Quick start guide

### 1. Install the bootloader (one-time)
> Details: [docs/bootloader/README.md](../bootloader/README.md)

1. Use STM32CubeProgrammer to perform a **Full Chip Erase**.
2. Program `AGR_Bootloader.bin` to address `0x08000000`.

### 2. Open the SDK project
1. Download the ZIP for your board revision (`Rev1.1.zip` / `Rev2.0.zip`) from Releases and extract it.
2. In STM32CubeIDE, go to **Import → Existing Projects into Workspace**.
3. Select the extracted folder (the one containing the `.project` file).
4. Build (Ctrl+B) — the post-build scripts run automatically.

### 3. Upload firmware
- **During development**: use STM32CubeIDE Debug (F11) via SWD, start address `0x08040000`
- **For distribution**: PhAI Studio → FW Upload → select `XM10_X_X_X_X.bin`

### 4. Update KIT H10 firmware
> Details: [docs/kit-h10-firmware/README.md](../kit-h10-firmware/README.md)

Copy the bundled H10 FW binaries to a USB drive, connect it to the H10, and follow the update procedure.

## Known issues

- RAM_D2 usage in the Rev1.1 SDK reaches 98.65%. Exercise caution when allocating large buffers.
- `version_generator.py` reads the git tag from the current directory. Tags may differ between the SDK repository and the development repository — verify `version.h` manually if needed.
- Python must be on the system `PATH` for the post-build scripts to run. If it is not recognized even after restarting STM32CubeIDE, check your system environment variables.
- libXM_Lib.a is built with `-Og -g3` (Debug). The `.a` file is 66–88 MB due to debug symbols, but this has no effect on the final Flash binary size.

## Note for v2.1.0 (Pre-Release) users

Two issues found in v2.1.0 were fixed in v2.1.1:

1. **Missing `--whole-archive` linker flag** → HAL `__weak` callbacks not overridden → `vPortFree` heap corruption
2. **`-O2 -g0` build** → Live Expressions and breakpoints did not work

**Use v2.1.1. Do not use v2.1.0.**
