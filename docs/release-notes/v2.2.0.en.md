# XM10 Extension Module SDK v2.2.0

> **Release date**: 2026-05-18 | **Target HW**: Rev 1.1 / Rev 2.0 | **KIT H10 FW**: v2.3.0+

---

## Overview

This release standardizes **user function naming** and makes **multi-task APIs** available on both board revisions.

- User functions renamed: `User_Setup` / `User_Loop` → **`Control_Setup` / `Control_Loop`** (the old names are no longer supported — please update your function names)
- Folder renamed: `XM_Apps/User_Algorithm/` → **`XM_Apps/Control_Task/`**
- **Auxiliary task API + data-sharing protection API** added to Rev 1.1 — you can now write multi-task code in exactly the same way on either Rev 1.1 or Rev 2.0
- Two new learning examples added (Ex.38, Ex.39)
- One new task-structure guide added (`docs/api-reference/09-task-creation.md`)

Your existing code continues to work as-is. The new names are more descriptive, so use them for any new code you write.

## What's New

### 1. Renamed user functions

The two functions you write have been renamed from `User_Setup` / `User_Loop` to **`Control_Setup` / `Control_Loop`**. The new names make their intent explicit — this is where you put your control code.

```c
// Before
void User_Setup(void) { /* initialization */ }
void User_Loop(void)  { /* runs every 1 ms */ }

// This release (recommended)
void Control_Setup(void) { /* initialization */ }
void Control_Loop(void)  { /* runs every 1 ms */ }
```

**Your existing code keeps working.** The SDK internally accepts both the old and new names. Use the new names for any new code you write.

The folder has been renamed from `XM_Apps/User_Algorithm/` to `XM_Apps/Control_Task/` for the same reason — aligning with the naming convention used across other company modules (CM-WH, etc.).

### 2. Auxiliary task API added to Rev 1.1

The following APIs, previously available only on Rev 2.0, are now included in **Rev 1.1 as well**. You can write multi-task code in exactly the same way regardless of which board you use.

```c
// Run a heavy computation once (e.g., training, FFT)
XmTaskHandle_t XM_Task_CreateOneShot(...);

// Run a periodic auxiliary task (e.g., compute average every 10 ms)
XmTaskHandle_t XM_Task_CreatePeriodic(...);

// Check completion / clean up
bool XM_Task_IsComplete(XmTaskHandle_t h);
void XM_Task_Delete(XmTaskHandle_t h);

// Mutex for safely sharing data between two tasks
XmMutexHandle_t XM_Mutex_Create(void);
bool            XM_Mutex_Lock(XmMutexHandle_t m, uint32_t timeout_ms);
void            XM_Mutex_Unlock(XmMutexHandle_t m);
```

The existing `XM_BgTask_Create` still works (marked deprecated only). Use the new API for new code.

## Rev 1.1 ↔ Rev 2.0 parity

Previously, a few features existed only on Rev 2.0. Starting with this release, **the user code area API is identical on both boards**.

| Feature | Rev 1.1 | Rev 2.0 |
|---------|---------|---------|
| User function names (`Control_Setup`/`Loop`) | ✅ | ✅ |
| Auxiliary task API (`XM_Task_*`) | ✅ (from v2.2.0) | ✅ |
| Data-protection API (`XM_Mutex_*`) | ✅ (from v2.2.0) | ✅ |
| Ex.38 / Ex.39 learning examples | ✅ (from v2.2.0) | ✅ |
| Task-structure guide | ✅ (from v2.2.0) | ✅ |
| ETH / PSRAM / RTC | ❌ (hardware not present) | ✅ |

The student learning course can now be completed identically on either Rev 1.1 or Rev 2.0.

## Compatibility notes

### Migrating from v2.1.1 to v2.2.0

The only required change is renaming your entry-point functions (the old names are no longer supported).

- Rename `User_Setup` / `User_Loop` → `Control_Setup` / `Control_Loop`
- `XM_BgTask_Create` can stay as-is — it still works
- If you leave your user code folder in the old location, the SDK will find it automatically. However, freshly extracted ZIP archives contain only `Control_Task/` — copy your code into that folder

### Starting a new project

- Write `Control_Setup()` / `Control_Loop()` inside `XM_Apps/Control_Task/control_task.c`
- If you need an auxiliary task, follow the patterns in `Ex.38` / `Ex.39`

## Changed files

Internal system code is bundled in `libXM_Lib.a` (static library), so there is nothing you need to do on your end. The library was rebuilt for v2.2.0 to include:

- New task management code (`xm_task_manager`)
- Automatic mapping from old to new function names (`user_compat`)
- Diagnostics and measurement utilities (`diag_perf`, `hardfault_dump`, `xm_imu_diag` (Rev 1.1) / `xm_periph_stimulus` + `xm_production_od` (Rev 2.0))
