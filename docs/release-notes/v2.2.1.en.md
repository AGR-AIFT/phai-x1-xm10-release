# XM10 Extension Module SDK v2.2.1

> **Release date**: 2026-05-19 | **Target HW**: Rev 1.1 / Rev 2.0 | **KIT H10 FW**: v2.3.0+

---

## At a Glance

**This is a patch release that fixes a problem where the downloaded SDK failed with 22 "undefined reference" errors on a STM32CubeIDE clean build.** The root cause was missing source files for certain modules during the library build step.

- Rev 2.0 SDK: replaced with a new `libXM_Lib.a`. All 169/169 link steps pass on a clean build.
- Rev 1.1 SDK: minor consistency fixes in the same spirit (FreeRTOS config + USB MSC diagnostic function).
- Board revision comparison docs improved — it was never clearly stated anywhere that building with the wrong ZIP causes the built-in button/LED pins to be off by one.

**Existing user code continues to work as-is.** No API or behavioral changes; build environment is unchanged. If you were building successfully with v2.2.0, you do not need to upgrade. If your build was failing, re-download using this ZIP.

## Download

| File | Target board |
|------|-----------|
| **Rev1.1.zip** | XM10 Rev 1.1 (early development board) |
| **Rev2.0.zip** | XM10 Rev 2.0 (latest board with Ethernet / PSRAM / RTC) |

Extracting the archive produces a single folder. That folder is both the STM32CubeIDE import root and the Claude Code working directory.

> Download the ZIP that matches your board revision. If the label is unclear, a quick visual check works: **if the board has an RJ45 Ethernet port it is Rev 2.0; if not, it is Rev 1.1**. Building with the wrong Rev's ZIP will compile successfully but the MCU pin mapping for the built-in button/LED will be off by one. For a detailed comparison, see [docs/hardware/README.md — Board Revision Comparison](https://github.com/AGR-EXO/Extension_Module/blob/v2.2.1/docs/hardware/README.md#보드-리비전-비교).

## Changes

### 1. Fixed 22 build errors in the Rev 2.0 SDK

Fixed a problem where performing a clean build in STM32CubeIDE immediately after downloading produced 22 link errors of the following form:

```
undefined reference to `CdcDopRouter_Init'
undefined reference to `CdcDopRouter_Process'
undefined reference to `USBH_DiskIO_GetDiag'
undefined reference to `USBH_DiskIO_ResetDiag'
undefined reference to `XM_Ethernetif_GetMdioId'
undefined reference to `g_eth_rx_packet_count'
undefined reference to `xTaskGetHandle'
... (22 errors total)
```

The SDK has been updated with a new `libXM_Lib.a` and the corresponding source files, and all 169/169 link steps pass on a clean build.

### 2. Stability improvements for the Rev 1.1 SDK

Rev 1.1 itself had no link failures, but a small consistency issue was addressed: certain functions called by the library were missing from the SDK tree.

- `Compatible/FATFS/Target/usbh_diskio.c` — restored missing USB MSC diagnostic function definitions
- `Core/Inc/FreeRTOSConfig.h` — added the `INCLUDE_xTaskGetHandle = 1` macro

### 3. Improved board revision comparison documentation

Fixed a broken link that was the entry point for identifying your board revision, and filled in the previously empty comparison table.

- `docs/hardware/README.md` — added per-revision MCU pin columns to the built-in button table; filled in the comparison table body (RJ45 / channel LEDs / PSRAM / button pins / ZIP mapping)
- `examples/README.md` — added a note describing the symptoms when using a ZIP for the wrong board revision
- `docs/api-reference/03-led-btn-control.md` — added a Rev mismatch entry to the "Common Mistakes" table
- `docs/troubleshooting.md` — new section "Board Revision / SDK ZIP Mismatch" (symptoms, pin table, diagnostic code, resolution steps)
- `README.md` / `CLAUDE.md` / `docs/find-it.md` — replaced broken architecture comparison table links with unified links to the new `hardware/README` comparison table
