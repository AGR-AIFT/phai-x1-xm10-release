# XM10 Extension Module SDK v2.4.1

> **릴리즈 날짜**: 2026-07-24 | **대상 HW**: **Rev 2.0 전용** | **KIT H10 FW**: v2.3.0+

---

## 한눈에 보기

**Rev 2.0 에서 C 표준 라이브러리를 바로잡은 패치 릴리즈**입니다. 실수를 출력하는 `printf("%f", ...)` 와 동적 메모리 `malloc()` 이 이전에는 조용히 실패했는데, 이번 릴리즈에서 정상 동작합니다. 새 예제나 API 변경은 없습니다.

- **실수 `printf`(`%f`)와 `malloc()` 이 이제 동작합니다** — 이전에는 힙(heap) 상한이 잘못된 메모리 영역을 기준으로 잡혀, `malloc()` 과 이를 내부적으로 쓰는 실수 `printf` 가 값을 내보내지 못했습니다. 힙 설정을 바로잡아 해결했습니다. (예: `printf("cur=%.2f\n", value);`)
- **여러 태스크에서 써도 안전합니다** — `malloc`/`printf` 계열을 여러 FreeRTOS 태스크가 동시에 호출해도 내부 자료구조가 깨지지 않도록 표준 라이브러리 락을 FreeRTOS 에 연결했습니다.
- **빌드 시스템 일치** — CubeIDE 와 CMake 두 경로가 정확히 같은 결과를 내도록 빌드 파일 생성 로직을 바로잡았습니다.
- **USB 로그 디코더가 설치형 실행 파일로** — 파이썬 설치 없이 바로 쓰는 **XM10 Log Decoder** 로 대체되었습니다(아래 참고).

## 무엇이 바뀌었나 — 실수 `printf` / `malloc` (핵심)

Rev 2.0 은 부팅 과정에서 스택(stack)을 DTCMRAM 최상단으로 옮기는데, 표준 라이브러리 힙은 그와 다른 영역인 RAM_D1 에 있습니다. 그런데 힙의 상한선이 힙이 실제로 위치한 RAM_D1 이 아니라 스택 꼭대기를 기준으로 잡혀 있었습니다. 그 결과 힙을 확장하는 내부 함수 `_sbrk()` 가 **첫 호출부터 실패**했고, `malloc()` 과 이를 내부적으로 사용하는 실수 `printf`(`%f`, `%e`, `%g`)가 값을 출력하지 못했습니다.

이번 릴리즈에서 힙 상한을 **RAM_D1 의 실제 최상단**으로 바로잡아, 아래 코드가 정상 동작합니다.

```c
float value = 3.14f;
printf("cur=%.2f\n", value);   // 이제 "cur=3.14" 출력 (이전에는 빈 값/깨짐)

char *buf = malloc(64);        // 이제 유효한 포인터 반환
```

- **Rev 1.1 은 영향 없음** — Rev 1.1 은 스택과 힙이 같은 메모리 영역에 있어 이 문제가 애초에 발생하지 않았습니다. Rev 1.1 SDK 는 v2.3.1 그대로입니다.
- **표준 라이브러리 멀티태스크 안전** — 위 수정과 함께, `malloc`/`free`/`printf` 계열이 여러 태스크에서 동시에 호출돼도 안전하도록 처리했습니다. 별도로 신경 쓸 것은 없습니다.

## USB 로그 디코더 — XM10 Log Decoder

USB 메모리(MSC)에 저장된 로그 파일(`.bin`)을 CSV 로 변환하는 도구가 **설치형 실행 파일**로 바뀌었습니다.

- 기존 `PythonDecoder/` 안의 파이썬 스크립트(MSC · Legacy) 대신, [Releases 페이지](https://github.com/AGR-EXO/Extension_Module/releases)에서 `XM10LogDecoder_Setup_*.exe` 를 받아 설치하면 됩니다. **파이썬 설치가 필요 없습니다.**
- 로그 포맷 버전(신규/구버전)을 자동 인식하고, **여러분이 정의한 임의의 로그 구조**도 그대로 CSV 로 풀어줍니다(열 제목 = 여러분이 지정한 필드 이름).
- USB-CDC 로 나오는 데이터를 **실시간 수신**하는 코드를 직접 짜고 싶다면, `PythonDecoder/CDC/` 파이썬 샘플이 그대로 남아 있습니다.

> 자세한 사용법: 리포지토리의 [`PythonDecoder/README.md`](https://github.com/AGR-EXO/Extension_Module/blob/v2.4.1/PythonDecoder/README.md) 참고.

### Release 첨부 파일

> **부트로더 · KIT H10 펌웨어 · 컨텐츠 파일은 v2.3.0 과 동일**하며, 편의를 위해 [v2.4.1 릴리즈](https://github.com/AGR-EXO/Extension_Module/releases/tag/v2.4.1)에도 같은 파일을 그대로 첨부했습니다 (`AGR_Bootloader.bin` / `SUIT_H10_Binary_20260716.zip` / `SUIT_ContentsFiles.zip`). 이미 v2.3.0/v2.3.1 기준으로 설치·업데이트하셨다면 추가 작업이 없습니다.

### 준비물 안내

빌드 마무리 단계(업로드용 `.bin` 생성)가 **Python** 을 사용합니다. 아직 설치하지 않았다면 [개발 환경 구축](https://github.com/AGR-EXO/Extension_Module/blob/v2.4.1/docs/getting-started/02-software-setup.md) 의 안내대로 Python 3.10+ 를 설치해 주세요 (PATH 등록 필수).

## 개선 상세

### 표준 라이브러리 (핵심)

- **실수 `printf` / `malloc` 정상화** — 힙 상한을 RAM_D1 최상단으로 바로잡아, `_sbrk()` 가 첫 호출부터 실패하던 문제를 해결했습니다. 실수 서식(`%f` 등)과 동적 메모리 할당이 정상 동작합니다.
- **멀티태스크 안전** — 표준 라이브러리 내부 락을 FreeRTOS 뮤텍스에 연결해, 여러 태스크의 동시 `malloc`/`printf` 호출에서도 힙이 손상되지 않도록 했습니다.

### SDK 빌드

- **CMake · CubeIDE 결과 일치** — 빌드 파일 생성기가 실수 `printf` 링커 옵션과 링커 Other-flags 를 누락하던 문제를 바로잡아, 어느 빌드 경로로 빌드하든 동일한 펌웨어가 나오도록 했습니다.

### 도구 · 문서

- **USB 로그 디코더 설치형 실행 파일화** — 위 [USB 로그 디코더](#usb-로그-디코더--xm10-log-decoder) 참고.
- **디버그 정지 안내 보강** — 디버그 시작 시 `main()` 정지와 `Break at address "0x0800xxxx" ... no debug information`(부트로더 영역) 팝업이 **정상 동작**임을 트러블슈팅 문서에 추가했습니다. `Resume`(F8) 로 진행하면 됩니다.
