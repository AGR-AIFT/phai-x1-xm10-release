# XM10 Extension Module SDK v2.2.0

> **릴리즈 날짜**: 2026-05-18 | **대상 HW**: Rev 1.1 / Rev 2.0 | **KIT H10 FW**: v2.3.0+

---

## 한눈에 보기

이번 버전은 **사용자 함수 이름을 정리하고**, **여러 작업을 동시에 돌리는 방법** 을 양 리비전에서 똑같이 쓸 수 있도록 평준화한 업데이트입니다.

- 사용자 함수 이름: `User_Setup` / `User_Loop` → **`Control_Setup` / `Control_Loop`** (예전 이름으로 짠 코드도 그대로 동작합니다)
- 폴더 이름: `XM_Apps/User_Algorithm/` → **`XM_Apps/Control_Task/`**
- Rev 1.1 에도 **보조 작업(task) API + 데이터 공유 보호 API** 추가 — 이제 Rev 1.1 / Rev 2.0 어느 보드든 똑같은 방식으로 멀티 작업 짤 수 있어요
- 학습 예제 2 개 추가 (Ex.38, Ex.39)
- 작업 구조 가이드 문서 1 편 추가 (`docs/api-reference/09-task-creation.md`)

기존 자산을 그대로 사용해도 됩니다. 새 이름이 더 직관적이라 새로 짤 때 권장.

## 새로 추가된 것

### 1. 사용자 함수 이름 정리

이전까지 사용자가 작성하는 두 함수의 이름이 `User_Setup` / `User_Loop` 였는데, 이번 버전부터 **`Control_Setup` / `Control_Loop`** 으로 통일했습니다. "제어 코드를 여기에 쓴다" 라는 의도가 더 명확하기 때문이에요.

```c
// 이전
void User_Setup(void) { /* 초기화 */ }
void User_Loop(void)  { /* 1 ms 주기 반복 */ }

// 이번 버전 (권장)
void Control_Setup(void) { /* 초기화 */ }
void Control_Loop(void)  { /* 1 ms 주기 반복 */ }
```

**기존 코드는 그대로 둬도 됩니다.** SDK 내부에서 옛 이름과 새 이름을 둘 다 받아들이도록 처리해 두었어요. 새로 시작하는 코드는 새 이름으로 쓰시면 됩니다.

폴더 이름도 같은 맥락에서 `XM_Apps/User_Algorithm/` → `XM_Apps/Control_Task/` 로 바뀌었습니다. 회사 다른 모듈 (CM-WH 등) 과 폴더 명명 규칙을 맞춘 결과예요.

### 2. Rev 1.1 에도 보조 작업(task) API 추가

Rev 2.0 에만 있던 다음 API 가 이제 **Rev 1.1 에도 같이 들어갑니다**. 어떤 보드를 쓰든 동일한 방식으로 멀티 작업 코드를 짤 수 있어요.

```c
// 1회만 실행되는 무거운 계산 (예: 학습, FFT)
XmTaskHandle_t XM_Task_CreateOneShot(...);

// 주기적으로 도는 보조 작업 (예: 10ms 마다 평균 계산)
XmTaskHandle_t XM_Task_CreatePeriodic(...);

// 작업 끝났는지 확인 / 정리
bool XM_Task_IsComplete(XmTaskHandle_t h);
void XM_Task_Delete(XmTaskHandle_t h);

// 두 작업이 같은 데이터를 안전하게 주고받기 위한 잠금
XmMutexHandle_t XM_Mutex_Create(void);
bool            XM_Mutex_Lock(XmMutexHandle_t m, uint32_t timeout_ms);
void            XM_Mutex_Unlock(XmMutexHandle_t m);
```

기존 `XM_BgTask_Create` 도 그대로 동작합니다 (deprecated 표시만 추가). 새 코드는 새 API 권장.

## Rev 1.1 ↔ Rev 2.0 평준화

이전까지는 Rev 2.0 에만 있던 기능이 몇 개 있었지만, 이번 버전부터 **사용자 코드 영역의 API 는 두 보드가 동일**합니다.

| 항목 | Rev 1.1 | Rev 2.0 |
|------|---------|---------|
| 사용자 함수 이름 (`Control_Setup`/`Loop`) | ✅ | ✅ |
| 보조 task API (`XM_Task_*`) | ✅ (v2.2.0 부터) | ✅ |
| 데이터 보호 API (`XM_Mutex_*`) | ✅ (v2.2.0 부터) | ✅ |
| Ex.38 / Ex.39 학습 예제 | ✅ (v2.2.0 부터) | ✅ |
| 작업 구조 가이드 | ✅ (v2.2.0 부터) | ✅ |
| ETH / PSRAM / RTC | ❌ (HW 부재) | ✅ |

사용자 학습 코스는 Rev 1.1 / Rev 2.0 어느 쪽이든 동일하게 진행할 수 있어요.

## 호환성 안내

### 기존 v2.1.1 코드를 v2.2.0 SDK 로 올릴 때

특별히 할 일 없습니다. 새 SDK 로 그냥 컴파일하면 됩니다.

- 옛 함수 이름 (`User_Setup` / `User_Loop`) 그대로 두어도 동작
- 옛 API (`XM_BgTask_Create`) 그대로 두어도 동작
- 사용자 코드 폴더는 옛 위치에 그대로 두면 자동으로 새 위치 (`Control_Task/`) 로 찾아갑니다 (단, ZIP 새로 풀면 `Control_Task/` 만 들어 있어요 — 그 안에 본인 코드를 옮기세요)

### 새로 시작하는 코드

- `XM_Apps/Control_Task/control_task.c` 안에 `Control_Setup()` / `Control_Loop()` 작성
- 보조 task 가 필요하면 `Ex.38` / `Ex.39` 패턴 참고

## 변경 파일

내부 시스템 코드는 `libXM_Lib.a` (정적 라이브러리) 에 묶여 있어 사용자 입장에서는 신경 쓸 일이 없습니다. v2.2.0 에서 .a 가 새로 빌드되어 다음이 반영되었습니다:

- 새 task 관리 코드 (`xm_task_manager`)
- 옛/새 함수 이름 자동 매핑 (`user_compat`)
- 진단/측정 유틸 (`diag_perf`, `hardfault_dump`, `xm_imu_diag` (Rev 1.1) / `xm_periph_stimulus` + `xm_production_od` (Rev 2.0))
