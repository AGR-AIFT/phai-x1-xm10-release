## CAN 통신 — 내 장치와 주고받기 (Rev 2.0)

직접 만든 CAN-FD 장치나 클래식 CAN 장치를 CAN-FD #2 포트(센서 허브를 연결하는 포트)에 연결합니다.

```c
#include "xm_api.h"

#define MY_DEVICE_ID  (0x20U)

static uint8_t s_seq = 0U;   // 명령 순번
static uint8_t s_led = 0U;   // 장치에 보낼 LED 값

void Control_Setup(void)
{
    XM_CanAttachDevice(MY_DEVICE_ID);                     // 장치 번호 등록 — Control_Setup() 안에서만
}

void Control_Loop(void)
{
    XmCanFrame_t f;
    if (XM_CanReadLatest(MY_DEVICE_ID, 1, &f)) { /* 주기 데이터의 최신값 — 새 값인지는 f.seq 로 */ }

    const uint8_t cmd[2] = { s_seq, s_led };
    if (XM_CanSend(MY_DEVICE_ID, cmd, sizeof(cmd)) == XM_CAN_OK) { s_seq++; }   // XM_CAN_OK 는 0 — 꼭 == 로
}
```

| 방법 | 함수 |
|------|------|
| 장치 API — 장치 번호를 정해 데이터 · 살아있음 · 명령 | `XM_CanAttachDevice` · `XM_CanReadLatest` · `XM_CanSend` · `XM_CanIsConnected` · `XM_CanGetStats` |
| 자유 송수신 — ID 와 데이터만 | `XM_CanSendFrame` · `XM_CanReadFrame` · `XM_CanSubscribe` · `XM_CanReadLatestById` |
| 클래식 CAN 모드 | 내 코드에 `XM_CanBusMode()` 를 만들어 `XM_CAN_BUS_CLASSIC` 을 돌려줍니다(기본 1 Mbit/s) — 이때 센서 허브는 동작하지 않습니다 |
| 동기 신호 · XM10 하트비트 | `XM_CanEnableSync` · `XM_CanEnableHeartbeat` |

- 기본 버스는 CAN-FD 1 Mbit/s / 5 Mbit/s, 샘플 포인트 75 % 입니다. 한 포트에 클래식 장치와 CAN-FD 장치를 함께 연결하지 마세요.
- XM10 보드에는 CAN-FD #2 쪽 120 Ω 종단 저항이 있습니다. 장치 쪽 끝에 하나를 둡니다.
- 장치는 4 대까지, 장치 번호는 1 ~ 127 중 예약 번호와 센서 허브 번호를 뺀 번호를 씁니다(`XM_CanIsDeviceIdAllowed()`).
- 자세히: [CAN 통신](../api-reference/11-canbus.md) · [`xm_api_canbus.h`](../api-reference/ref/xm-api-canbus.md)

## CANopen 장치 다루기 (Rev 2.0)

CANopen(CiA 301) 모터 드라이버를 클래식 CAN 모드에서 다룹니다.

| 기능 | 함수 |
|------|------|
| NMT | `XM_CanOpenSendNmt` |
| 하트비트 감시(8 노드까지) | `XM_CanOpenWatchNode` · `XM_CanOpenGetNodeState` · `XM_CanOpenGetBootupCount` |
| SDO 빠른 읽기 · 쓰기(4 B 이하, 한 번에 하나, 기다리지 않음) | `XM_CanOpenSdoRead` · `XM_CanOpenSdoWrite` · `XM_CanOpenSdoGetResult` |

- SDO 응답이 500 ms 안에 없으면 시간 초과이고, 그 뒤 1.5 초 동안 새 요청을 받지 않습니다.
- 1 kHz 명령은 SDO 로 PDO 를 설정한 뒤 PDO 와 SYNC 로 합니다(Ex.47).
- **통신이 끊기면 드라이버가 스스로 멈추게** 하세요 — XM10 하트비트(`XM_CanEnableHeartbeat`)를 드라이버의 하트비트 소비로 지켜보게 하는 것이 안전 정지의 핵심입니다.
- 자세히: [CANopen 장치 다루기](../api-reference/12-canopen.md) · [`xm_api_canopen.h`](../api-reference/ref/xm-api-canopen.md)

## IMU Hub 센서 보정 (Rev 2.0)

CAN-FD 로 연결된 IMU Hub 의 센서를 케이스나 옷에 넣은 채로 보정합니다. 함수는 모두 기다리지 않습니다.

| 함수 | 하는 일 |
|------|------|
| `XM_ImuCalibStart(채널, 항목)` | 시작 — **한 번만** 부릅니다 |
| `XM_ImuCalibGetStatus(채널, &상태)` | 상태 보기 |
| `XM_ImuCalibFinish` · `XM_ImuCalibAbort` | 움직이는 단계 끝내기(저장) · 중단 |
| `XM_ImuCalibQuerySupported` · `XM_ImuCalibGetSupported` | 채널별 지원 항목 |

- 항목: 자이로 영점 · 지자기 · 가속도 간이 · 가속도 정밀. MTi-630 은 자이로 영점 · 지자기만 됩니다.
- 제어 모드(`XM_CTRL_CONTROL`)에서는 시작할 수 없습니다. 보정 중인 채널은 `XM.status.imu_hub.connected_mask` 비트가 꺼지니 그 값으로 제어하지 마세요.
- EBIMU 의 지자기 · 가속도 정밀을 중단하거나 움직이는 시간 상한을 넘기면 모든 채널의 전원이 약 2 초 꺼졌다 켜집니다.
- **IMU Hub 펌웨어가 보정 기능을 갖고 있어야 합니다.** 옛 펌웨어면 '지원하지 않음' 또는 '응답 없음' 으로 끝납니다.
- 자세히: [IMU Hub 센서 보정](../api-reference/13-imu-calibration.md) · [`xm_api_imu_calib.h`](../api-reference/ref/xm-api-imu-calib.md)
- 예제: [Ex.48 IMU Hub Calibration](https://github.com/AGR-AIFT/phai-x1-xm10-release/tree/Develop/examples/48_IMU_Hub_Calibration/) — 버튼으로 자이로 영점 · 지자기 보정 · 중단. (보드 확인 전) <!-- board-check -->

## Total Data 가 4 바이트 커졌습니다 (Rev 2.0)

- Total Data(`0x20`)에 `imu_hub_timestamp_b` 칸(CAN-FD 로 연결된 IMU Hub 의 3 ~ 5번 센서 시각)이 생겨 365 B 에서 369 B 가 되었습니다.
- 함께 보내는 **구조체 로깅의 등록 한도가 4 바이트 줄었습니다.** Total Data 를 켠 채 등록 한도에 딱 맞춰 쓰던 구조체는 등록이 거절될 수 있습니다. 거절되면 구조체를 4 바이트 줄이거나 주기를 낮추세요.
- **PC 프로그램** — `Rev2.0.zip` 에 든 `xm10` 도구는 새 크기를 압니다. 새 크기를 모르는 PhAI Studio 에서는 Total Data 가 보이지 않을 수 있습니다. 그때는 `xm10` 도구로 보세요.
- **Rev 1.1 보드**는 Total Data 가 그대로(365 B)입니다. `Rev1.1.zip` 에 든 `xm10` 도구를 쓰세요. 레포의 `pc-data-tool/` 은 Rev 2.0 v2.10.0 에 맞춰져 있습니다.

## 고친 것

| 무엇 | 내용 |
|------|------|
| Total Data 값의 흔들림 (Rev 2.0) | Total Data(`0x20`)에 담긴 IMU Hub 센서 시각이 50 ms · 5 초마다 같은 값으로 두 번 오거나 하나를 건너뛰던 문제를 고쳤습니다 |
| 1회성 태스크 (Rev 2.0) | `XM_Task_CreateOneShot()` 으로 만든 태스크가 끝난 뒤 지우거나(`XM_Task_Delete()`) 멈췄다 다시 시작할 때 이미 해제된 메모리를 건드리던 문제를 고쳤습니다 |
| `XM_SetChannelLedRGB(ch, 0, 0, 0)` (Rev 2.0) | 문서대로 그 채널이 시스템 자동 표시로 돌아갑니다. 전에는 꺼진 채 남았습니다 — **0,0,0 을 '끄기' 로 쓰던 코드는 동작이 바뀝니다** |
| Release 빌드 설정 (Rev 2.0 SDK) | STM32CubeIDE 에서 빌드 설정을 Release 로 바꾸면 헤더를 찾지 못해 빌드가 실패하던 문제를 고쳤습니다 |
| `xm_api.h` 가 가져오는 이름 (Rev 2.0) | XM10 내부 이름까지 함께 가져와, 내 코드에서 같은 이름(예: 상태 · 통신 상수 이름)을 쓰면 빌드되지 않을 수 있던 문제를 고쳤습니다. 그 대신 `xm_api.h` 를 통해 우연히 보이던 내부 함수 · 매크로를 쓰던 코드는 이제 빌드되지 않을 수 있습니다 — 헤더에 선언된 XM API 로 바꿔 주세요. `snprintf` · `abs` 같은 표준 함수는 그대로 쓸 수 있습니다 |
