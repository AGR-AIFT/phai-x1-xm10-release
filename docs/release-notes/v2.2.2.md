## 예제 코드 정리 — 9 건

사용자가 예제를 따라 만들 때 가장 자주 발을 거는 패턴들이라, 짧은 패치라도 모아 릴리즈합니다.

### Critical — 사용자가 그대로 따라 쓰면 안 될 패턴

- **Ex.31 (Friction_Comp_DOB)** — `MAX_TORQUE_NM` 이 같은 파일에서 두 번 `#define` 되어 있어 (`8.0f` 뒤에 `5.0f`) 컴파일러가 `redefined` 경고를 출력하고 있었습니다. 두 정의 중 `5.0f` 가 실제 동작 값이라 토크 클램프는 5 Nm 로 정상이지만, 위쪽 주석은 8 Nm 를 가리키고 있어 사용자가 "왜 8 까지 안 가지?" 로 혼선이 가능. **5.0 Nm 단일 정의로 통합**.
- **Ex.08 (CDC_Sensor_Print) · Ex.13 (Resistive_Mode)** — 64 byte 스택 버퍼에 bare `sprintf(...)` 를 쓰고 있었습니다. 포맷 문자열이 늘어나면 silent stack overflow 위험이 있어 **`snprintf(buf, sizeof(buf), ...)` 로 교체**. Ex.08 은 "CDC 디버그 print 모범 예시" 의 위치라 사용자가 그대로 복사해 갈 가능성이 높아 우선순위 높음.

### High — 동작은 하지만 사용자를 혼동시키는 부분

- **Ex.15 (Inverted_Pendulum)** — 디버그 라인의 고정소수점 출력에서 음수 부호가 사라지던 버그. 예를 들어 `theta = -0.35` 가 시리얼 로그에 `0.35` 로 찍혀, 골반이 한쪽으로 기울어졌는데도 부호 없이 표시돼서 PD 게인 튜닝 디버그가 어려웠습니다. **부호를 `%s` 로 prefix 분리** 해 `-0.35` 가 그대로 표시되도록 수정.
- **Ex.33 (Kinesthetic_Teaching)** — 재생 인덱스 전진 타이머가 "loop-count 매크로" 를 "ms 임계값" 으로 재활용하고 있었습니다. 우연히 둘 다 `10` 이라 동작은 했지만, 둘 중 하나라도 바뀌면 깨지는 구조. **`REPLAY_STEP_MS = 10U` 매크로 신설** 로 의미를 분리.
- **Ex.36 (OnDevice_Kinesthetic_Learning)** — TSM `Active` 상태를 재진입할 때 `s_mode_lost_tick` 워치도그가 stale 한 값을 안고 있어, 첫 cycle 에서 곧바로 `STANDBY` 로 빠져버릴 수 있었습니다. **`Active_Entry` 에서 명시 리셋**. 더불어 BG 학습 task ↔ 전경 제어 사이의 다중 워드 volatile 한계를 헤더 주석에 남겨, "왜 Ex.38 에서는 mutex 를 쓰는데 여기서는 안 쓰지?" 의 답이 코드에서 보이도록 보강.

### Medium — 사용자가 흉내 내기엔 오해 소지가 있는 패턴

- **Ex.22 (CPG_Oscillator)** — AFO 의 frequency 적응 식이 phase advance **이후** 의 `sin(φ)` 를 쓰고 있어, 문서화된 Ronsse 2011 식 (`φ[k]` 사용) 과 한 스텝 어긋나 있었습니다. **`sin(φ[k]) / cos(φ[k])` 를 미리 계산** 해 두 업데이트 식이 같은 시점의 위상을 보도록 정렬.
- **Ex.24 (Virtual_Constraint)** — 5 차 Bézier basis 가 1 kHz 루프에서 `powf` 를 12 회 호출하고 있었습니다. **거듭곱 체인 (`s2 = s*s`, `s3 = s2*s`, ...) 으로 교체** — powf 가 사라져서 호출 비용이 곱셈 ~14 회로 떨어졌습니다.
- **Ex.26 (ILC)** — 보행 주기 1 회당 1 번만 호출되는데 함수 헤더에 그게 명시되지 않아 "1 kHz 루프에서 매번 USB send 하는 거 아닌가?" 오해를 줄 수 있었습니다. **호출 빈도 (≈ 1 Hz) 와 다른 빈도로 옮길 때의 가이드를 헤더 주석에 명시**.
- **Ex.16 (TinyAI Sensor_Fusion)** — NN raw logit 을 `× 100.0f` 해서 `Conf:%` 라벨로 출력 — 사용자가 보면 확률처럼 보이지만 실제는 softmax 가 아닌 raw 값. **라벨을 `Score:` 로, `× 100` 제거** 해 단위 그대로 노출. 헤더 주석에도 "raw logit" 임을 명시.

### Ex.36 (OnDevice Kinesthetic Learning) 은 Rev 2.0 전용 — 4 곳에 일관 표기

Ex.36 은 학습된 NN 가중치를 전원 OFF/ON 사이에 보존하기 위해 Internal Flash UserNV API (`XM_UserNV_Read/Write/Erase`) 를 사용합니다. 이 API 는 **Rev 2.0 의 `libXM_Lib.a` 에만 포함**되어 있어 Rev 1.1 에서는 link 단계에서 `undefined reference to XM_UserNV_*` 가 발생합니다.

지금까지는 코드도 문서도 이 사실을 알려주지 않아서 Rev 1.1 보드를 받은 사용자가 Ex.36 에서 막힐 때 원인을 짐작하기 어려웠습니다. 본 릴리즈에서 4 곳에 일관 표기를 넣었습니다.

| 위치 | 내용 |
|------|------|
| `examples/36_OnDevice_Kinesthetic_Learning/ondevice_kinesthetic_learning.c` 헤더 | `@warning Rev 2.0 전용` + 원인 + Rev 1.1 사용자 대안 (Ex.35 까지) |
| `examples/36_OnDevice_Kinesthetic_Learning/README.md` 상단 | 🛑 Rev 2.0 전용 안내 배너 |
| `docs/troubleshooting.md` 신규 섹션 | `undefined reference to XM_UserNV_*` 증상 — 원인 — 해결 절차 |
| `docs/tutorials/README.md` 41 예제 로드맵 | Ex.36 행에 "Rev 2.0 전용" 표기 |

> 본인 보드가 Rev 1.1 이면 Ex.35 (Multi-Layer Transparent Control) 까지 진행하시면 됩니다. Ex.36 의 NN 학습 + LQR 부분만 보고 싶다면 BTN1 long-press (Flash 저장) 만 제거하고 RAM 만 쓰도록 임시 수정해 학습용으로 활용 가능.

## 부수 — 빌드 sweep 도구

내부 검증 레포의 `tools/build_all_examples.sh` — 47 개 예제를 하나씩 사용자 코드 자리에 넣어가며 swap-build 해 PASS/FAIL + `.text` 크기 + 실패 로그를 자동 기록하는 스크립트가 추가됐습니다. 이번 코드 리뷰 라운드의 검증 근거가 이 도구이고, 다음 릴리즈부터 신규 예제 추가 시 회귀 검사 진입점으로 쓸 예정입니다. (사용자 측 SDK ZIP 에는 들어가지 않습니다 — 내부 검증 도구.)
