# XM10 Extension Module SDK v2.4.1

> **Release date**: 2026-07-24 | **Target HW**: **Rev 2.0 only** | **KIT H10 FW**: v2.3.0+

---

## At a Glance

**A patch release that fixes the C standard library on Rev 2.0.** Floating-point `printf("%f", ...)` and dynamic `malloc()`, which previously failed silently, now work. No new examples or API changes.

- **Float `printf` (`%f`) and `malloc()` now work** — previously the heap ceiling was pinned to the wrong memory region, so `malloc()` and the float `printf` that uses it internally produced no output. Fixed by correcting the heap configuration. (e.g. `printf("cur=%.2f\n", value);`)
- **Safe from multiple tasks** — the C library locks are now wired to FreeRTOS, so concurrent `malloc`/`printf` calls from several FreeRTOS tasks no longer corrupt internal state.
- **Build-system parity** — the CubeIDE and CMake build paths now produce exactly the same result.
- **USB log decoder is now an installable executable** — replaced by **XM10 Log Decoder**, which needs no Python install (see below).

## What Changed — Float `printf` / `malloc` (core)

On Rev 2.0 the boot process moves the stack to the top of DTCMRAM, while the C library heap lives in a different region (RAM_D1). The heap's upper bound, however, was pinned to the top of the stack rather than to RAM_D1 where the heap actually resides. As a result the internal heap-growth function `_sbrk()` **failed on its very first call**, and `malloc()` — along with the float `printf` (`%f`, `%e`, `%g`) that relies on it — produced no output.

This release corrects the heap ceiling to the **actual top of RAM_D1**, so the following now works:

```c
float value = 3.14f;
printf("cur=%.2f\n", value);   // now prints "cur=3.14" (previously empty/garbled)

char *buf = malloc(64);        // now returns a valid pointer
```

- **Rev 1.1 is unaffected** — on Rev 1.1 the stack and heap live in the same region, so this never occurred. The Rev 1.1 SDK is unchanged from v2.3.1.
- **Thread-safe standard library** — alongside the fix, `malloc`/`free`/`printf` are now safe to call concurrently from multiple tasks. Nothing extra to do on your side.

## USB Log Decoder — XM10 Log Decoder

The tool that converts USB mass-storage (MSC) log files (`.bin`) into CSV is now an **installable executable**.

- Instead of the Python scripts under `PythonDecoder/` (MSC · Legacy), download `XM10LogDecoder_Setup_*.exe` from the [Releases page](https://github.com/AGR-AIFT/phai-x1-xm10-release/releases) and install it. **No Python install required.**
- It auto-detects the log format version (new/legacy) and expands **any log structure you define** into CSV (column titles = your own field names).
- If you want to write code that receives USB-CDC data **in real time**, the `PythonDecoder/CDC/` Python samples remain in place.

> Full usage: see [`PythonDecoder/README.md`](https://github.com/AGR-AIFT/phai-x1-xm10-release/blob/v2.4.1/PythonDecoder/README.md).

## Details

### Standard library (core)

- **Float `printf` / `malloc` fixed** — the heap ceiling is corrected to the top of RAM_D1, fixing the `_sbrk()` first-call failure. Float format specifiers (`%f`, etc.) and dynamic allocation now work.
- **Thread-safe** — the C library's internal locks are wired to FreeRTOS mutexes, so concurrent `malloc`/`printf` from multiple tasks no longer corrupts the heap.

### SDK build

- **CMake · CubeIDE parity** — the build-file generator was dropping the float-`printf` linker option and the linker Other-flags; corrected so both build paths produce the same firmware.

### Tools · docs

- **USB log decoder as an installer** — see [USB Log Decoder](#usb-log-decoder--xm10-log-decoder) above.
- **Debug-halt guidance** — clarified in troubleshooting that halting at `main()` and the `Break at address "0x0800xxxx" ... no debug information` popup (bootloader region) are **normal**. Just press `Resume` (F8).
