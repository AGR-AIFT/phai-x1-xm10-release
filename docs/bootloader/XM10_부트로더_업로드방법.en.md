## 1. Overview

The XM10 Extension Module ships with the **AGR_BOOT V2** bootloader, which enables firmware updates over USB.

### What the Bootloader Does
- Validates app firmware at power-on (**signature + CRC-32 + HW revision check**)
- Receives app firmware uploads via the **USB CDC FTP** protocol
- **Automatically rolls back** to backup firmware if an update fails (after 3 consecutive boot failures)
- Supports both Rev1.1 and Rev2.0 hardware from a **single bootloader binary** (automatic GPIO-based HW revision detection)

### Required Tools

| Tool | Purpose | Download |
|------|---------|----------|
| **STM32CubeProgrammer** | Initial bootloader installation (SWD/JTAG) | [st.com](https://www.st.com/en/development-tools/stm32cubeprog.html) |
| **STM32CubeIDE** | App firmware build + SWD debugging | [st.com](https://www.st.com/en/development-tools/stm32cubeide.html) |
| **PhAI Studio** | USB FTP firmware upload | [studio.onephai.com](https://studio.onephai.com) |
| **ST-Link V3** | SWD debugging probe | Compatible with ST-Link V2/V3 |

## 2. Flash Memory Map

The STM32H743XI has 2 MB of internal Flash (Bank1 + Bank2).

```
┌──────────────────────────────────────────────────────────────┐
│ Address         │ Size    │ Region         │ Description      │
├──────────────────────────────────────────────────────────────┤
│ 0x08000000      │ 256 KB  │ Bootloader     │ AGR_BOOT V2       │
│                 │         │                │ (Bank1 S0-S1)     │
├──────────────────────────────────────────────────────────────┤
│ 0x08040000      │ 1 KB    │ FW Header      │ AGR_FwInfo_t      │
│                 │         │                │ (signature+CRC+version) │
├──────────────────────────────────────────────────────────────┤
│ 0x08040400      │ 767 KB  │ App (Active)   │ User app firmware │
│                 │         │                │ (Bank1 S2-S7)     │
├──────────────────────────────────────────────────────────────┤
│ 0x08100000      │ 768 KB  │ Backup Slot    │ Previous firmware backup │
│                 │         │                │ (Bank2 S0-S5)     │
├──────────────────────────────────────────────────────────────┤
│ 0x081C0000      │ 128 KB  │ Boot Config    │ AGR_BootConfig_t  │
│                 │         │                │ (Bank2 S6)        │
├──────────────────────────────────────────────────────────────┤
│ 0x081E0000      │ 128 KB  │ Reserved       │ Reserved for future use │
│                 │         │                │ (Bank2 S7)        │
└──────────────────────────────────────────────────────────────┘
```

> **Important**: The bootloader (0x08000000) and app (0x08040000) occupy completely separate regions.  
> Flashing the app over SWD does not damage the bootloader.

## 3. Initial Installation (Fresh Board, No Bootloader)

Follow this procedure for a brand-new board that has never had a bootloader, or for a board that was previously used without one.

### Step 1: Full Chip Erase

> **Why is this necessary?** If existing firmware starts at 0x08000000 as a single binary, its address will conflict with the bootloader after installation. Always erase the entire chip before proceeding.

1. Launch **STM32CubeProgrammer**
2. Connect an ST-Link to the board
3. Click **Connect** in the left panel (SWD or JTAG)
4. Select **Erasing & Programming** (download icon) from the left menu
5. Click the **Full chip erase** button at the top
6. Confirm the "Erase complete" message

### Step 2: Flash the Bootloader Binary

1. In the **Erasing & Programming** tab:
   - **File path**: select `AGR_Bootloader.bin` (download from the Release)
   - **Start address**: `0x08000000` (leave as default)
   - **Skip flash erase before programming**: unchecked (default)
   - **Verify programming**: checked
2. Click **Start Programming**
3. Confirm the "Download complete" + "Verification OK" messages

> **Using a Hex file**: Select `AGR_Bootloader.hex` and the address is set automatically.

### Step 3: Verify

1. Reset the board (or cycle power)
2. The bootloader starts and, finding no valid app firmware, enters **FTP mode**
   - A USB CDC port appears on the PC (COM port)
3. Proceed to **Step 4 or Step 5** to upload app firmware

## 4. App Firmware Upload — STM32CubeIDE (SWD Debugging)

This is the most common method during development. It writes firmware directly to Flash over SWD.

### One-Time Setup

**Configure the Debug Configuration:**

1. Go to **Run → Debug Configurations → STM32 C/C++ Application**
2. Create a new configuration or select an existing one
3. In the **Debugger** tab:
   - **Download**: ✅ checked
   - **Start address**: `0x08040000` (⚠️ This is NOT the default `0x08000000`!)
   - **Size**: `0x000C0000` (768 KB = Active Slot)
   - **Reset behaviour**: Software Reset

> **⚠️ Critical**: Set the Start address to `0x08040000`.  
> Leaving it at the default (`0x08000000`) **overwrites the bootloader**.

### Build & Debug

1. **Build** the project in STM32CubeIDE (Ctrl+B)
2. Post-Build scripts run automatically:
   - `size_report.py` → prints a memory usage report
   - `version_generator.py` → generates `version.h` from the git tag
   - `patch_fw_info.py` → patches the `fw_size` and CRC into the `.fw_header` section of the ELF
   - `fw_packager.py` → creates a packaged binary ready for FTP upload
3. Click **Debug** (F11) → app firmware is written to `0x08040400` over SWD
4. Debugging works normally (breakpoints, variable watch, etc.)

### Why SWD Debugging Is Compatible with the Bootloader

- The linker script (`STM32H743XIHX_FLASH.ld`) places app code at `0x08040400`
- The `.fw_header` section is placed at `0x08040000` so the bootloader can read the signature
- `boot_fw_info.c` embeds the `AGRBOOT` signature in the ELF, allowing the bootloader to recognize the app even after an SWD flash

## 5. App Firmware Upload — PhAI Studio (USB FTP)

This method uploads firmware using only a USB cable — no SWD debugger required.  
Recommended for **production environments**, **field updates**, and **end users**.

### Required Files

After a successful build, the `Debug/` folder contains the following files:

```
Debug/
├── Extension_Module.elf        ← for SWD debugging
├── Extension_Module.bin        ← for SWD flashing (includes FW Header)
├── Extension_Module.hex        ← for SWD flashing
├── Extension_Module_app.bin    ← for FTP upload (no FW Header)
└── XM10_X_X_X_X.bin           ← packaged binary for FTP upload ★
```

> **File to use in PhAI Studio**: `XM10_X_X_X_X.bin` (e.g., `XM10_2_0_1_0.bin`)  
> This file is generated by `fw_packager.py` and consists of a 1 KB `AGR_FwInfo_t` header followed by the app binary.

### Upload Procedure

1. Open **PhAI Studio**: [studio.onephai.com](https://studio.onephai.com)
2. Connect the XM10 board to the PC via USB cable
3. Confirm that PhAI Studio detects the device automatically
4. Select the **FW Upload** menu
5. Select the `XM10_X_X_X_X.bin` file
6. Start **Upload**
7. Monitor the progress bar — the board reboots automatically when complete
8. The bootloader validates the new firmware and launches the app

### Force-Enter FTP Mode

To switch to FTP mode while the app is running:
- Send the **Enter Bootloader** command from PhAI Studio
- Or call `AGR_Boot_RequestUpdate()` from within the app code

## 6. Post-Build Binary Generation

When you run **Build** in STM32CubeIDE, Post-Build scripts execute in the following order:

```
[Build]   GCC compile + link → Extension_Module.elf
           │
[Step 1]  size_report.py → memory usage report (printed to console)
           │
[Step 2]  version_generator.py → git tag → auto-generate version.h
           │
[Step 3]  patch_fw_info.py → patch ELF .fw_header (fw_size, fw_crc32)
           │                  → generate .bin, .hex, _app.bin
           │
[Step 4]  fw_packager.py → _app.bin + FwInfo header → XM10_X_X_X_X.bin
```

### Step Details

| Step | Script | Input | Output | Description |
|------|--------|-------|--------|-------------|
| 1 | `size_report.py` | `.elf` | console | Visualizes FLASH/RAM usage |
| 2 | `version_generator.py` | git tag | `version.h` | Defines `FW_VER_MAJOR/MINOR/PATCH/DEBUG` |
| 3 | `patch_fw_info.py` | `.elf` | `.bin`, `.hex`, `_app.bin` | Patches `fw_size`/CRC into `.fw_header` |
| 4 | `fw_packager.py` | `_app.bin` | `XM10_X_X_X_X.bin` | 1 KB header + app binary = FTP-ready package |

> **Python 3.x required**: All Post-Build scripts are written in Python.  
> Run `pip install pyyaml` (required for Data Map Code-Gen).

## 7. Bootloader Operation

### Boot Sequence

```
Power ON → bootloader starts (0x08000000)
    │
    ├─ Read Boot Config (Bank2 S6)
    │   └─ First boot: auto-create config with default values
    │
    ├─ Rollback check (boot_count >= 3?)
    │   └─ Yes: restore from backup slot
    │
    ├─ Validate app firmware
    │   ├─ Check "AGRBOOT\x01" signature
    │   ├─ CRC-32 verification (FTP upload only)
    │   └─ HW revision compatibility check
    │
    ├─ Validation passed → jump to app (0x08040400)
    │   └─ App calls AGR_Boot_ConfirmBoot() → reset boot_count
    │
    └─ Validation failed → enter FTP wait mode
        └─ Waiting for new firmware over USB CDC
```

### FTP Update Sequence

```
FW Upload started from PhAI Studio
    │
    ├─ [1] App switches to bootloader (writes magic value to RTC BKP0R + NVIC Reset)
    ├─ [2] Copy current Active FW → Backup Slot
    ├─ [3] Erase Active Slot
    ├─ [4] Receive new FW + write to Active Slot
    ├─ [5] CRC-32 verification
    ├─ [6] Update Boot Config (PENDING_CONFIRM)
    └─ [7] Reset → new app starts → ConfirmBoot() → complete
```

## 8. Troubleshooting

### "I installed the bootloader but the app won't run"

**Cause**: No app firmware present, or existing firmware is invalid.
1. Build in STM32CubeIDE and upload the app via Debug (F11)
2. Or upload `XM10_X_X_X_X.bin` through PhAI Studio

### "SWD debugging erased my bootloader"

**Cause**: The Debug Configuration had Start address set to `0x08000000`.
1. Change it to `0x08040000` (see Section 4)
2. Reinstall the bootloader (see Section 3)

### "PhAI Studio cannot find the device"

1. Check the USB cable connection
2. Verify the COM port in Windows Device Manager
3. Confirm the bootloader is in FTP mode — if the app is running, send "Enter Bootloader" from PhAI Studio first

### "After uploading firmware, the board kept rebooting and reverted to the previous version"

**Cause**: `AGR_Boot_ConfirmBoot()` was not called from the new firmware, triggering automatic rollback after 3 boot attempts.
- Check that `system_startup.c` calls `AGR_Boot_ConfirmBoot()` shortly after boot
- The default SDK code already includes this call — verify that `system_startup.c` has not been modified

### "The build succeeds but XM10_X_X_X_X.bin is not generated"

1. Verify Python 3.x is installed: `python --version`
2. Check the Post-Build script output in the Build Console for error messages
3. Confirm that script files exist in the `tools/build/` folder

### "STM32CubeProgrammer shows no data at 0x08040000 after reading"

**Cause**: The Start address was set incorrectly when uploading a `.bin` file directly via STM32CubeProgrammer.
- When uploading a `.bin` file, set Start address to `0x08040000`
- `.hex` files embed the address and are handled automatically

## 9. Important Notes

### What You Must Never Do

| Prohibited Action | Consequence |
|------------------|------------|
| Set Start address to 0x08000000 in STM32CubeIDE Debug | **Destroys the bootloader** |
| Upload only the app after a Full chip erase in STM32CubeProgrammer | **No bootloader → board cannot boot** |
| Write directly to the bootloader region (0x08000000–0x0803FFFF) | **Destroys the bootloader** |
| Arbitrarily erase the Boot Config region (0x081C0000) | **Resets boot configuration (auto-recovery occurs)** |

### Shared Notes for Rev1.1 / Rev2.0

- Both revisions use the **same bootloader binary** (HW revision is detected automatically via GPIO)
- Both revisions use the **same Flash memory map**
- App firmware is built against a separate **`libXM_Lib.a`** for each revision, but the bootloader is shared

### Python Environment Setup

To run the Post-Build scripts:
```bash
# After installing Python 3.x
pip install pyyaml
```

If STM32CubeIDE's Build Console cannot find Python:
- **Windows**: Add the Python installation path to the system `PATH` environment variable
- Restart STM32CubeIDE after making changes
