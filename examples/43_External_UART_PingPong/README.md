# Ex.43 — External UART Ping-Pong (보드끼리 시리얼로 대화하기)

> 🎯 **학습 목표**:
> - XM10 의 **External UART**(PD5/PD6)로 **바깥 장비와 직접 통신**한다.
> - 받은 바이트를 **콜백에서 복사만** 하고, 해석은 제어 루프에서 하는 이유를 이해한다.
> - **프레임 경계를 스스로 찾는** 바이트 상태기계를 직접 짜 본다.
>
> ⏱️ 권장 시간: 50분 | 🔧 난이도: ⭐⭐ | 🟢 **Rev 2.0 전용** (External UART = USART2)
> 🧰 사전 예제: [Ex.07 CDC Basic Print](../07_CDC_Basic_Print/) · [Ex.38 Periodic Background Task](../38_Periodic_Background_Task/)
> 📚 관련 docs: [보드 리비전 비교](../../docs/hardware/README.md#보드-리비전-비교)

> 🛑 **Rev 2.0 전용 — Rev 1.1 보드에서는 절대 이대로 배선하지 마세요.**
> Rev 1.1 에는 External UART 포트 자체가 없습니다(시리얼 포트는 발바닥 센서용 UART7/UART8 뿐).
> 게다가 **Rev 1.1 의 PD6 은 `USB_PWR_ON`, 즉 USB 전원을 켜고 끄는 출력 핀**입니다 —
> 여기에 상대 보드의 TX 를 물리면 출력끼리 맞부딪칩니다. 본인 보드 리비전을 먼저 확인하세요.
> (이 예제는 Rev 1.1 SDK 에는 포함되지 않습니다.)

---

## 1️⃣ 목표 — 이 예제로 무엇이 동작하나

XM10 **두 대**를 선으로 직접 이어서, 1초에 10번씩 서로 메시지를 주고받습니다.
같은 펌웨어를 두 보드에 굽기만 하면 됩니다.

| 요소 | 동작 |
|---|---|
| 송신 | 100ms 마다 5바이트 프레임 1개 (헤더 2 + 카운터 2 + 체크섬 1) |
| 수신 | 콜백이 링버퍼에 **복사만** → `Control_Loop()` 이 꺼내서 해석 |
| 확인 | 디버거 Live Expressions 로 송·수신 카운터와 상대 보드의 카운터를 관찰 |

상대는 XM10 이 아니어도 됩니다. 아두이노, PC, 다른 MCU 보드 — UART 를 쓰는 장비면
같은 방식으로 붙습니다. **주고받을 내용(프로토콜)은 여러분이 정합니다.**

---

## 2️⃣ External UART 란? — 무엇을 할 수 있는 포트인가

XM10 은 바깥 장비와 자유롭게 통신하라고 시리얼 포트 하나를 열어 둡니다.

### 📋 하드웨어 설정 — 상대 장비를 여기에 맞추세요

보드 쪽 설정은 **CubeMX(`.ioc`)에서 이미 고정**되어 있습니다. 아래가 그 실제 값입니다.
**상대 장비를 이 값에 맞추셔야 통신됩니다.**

| 항목 | 값 | 바꿀 수 있나 |
|---|---|---|
| 페리페럴 | **USART2** (비동기 모드) | ✗ |
| **TX 핀** | **PD5** (보드 넷 이름 `EXT_UART_TX`) | ✗ |
| **RX 핀** | **PD6** (보드 넷 이름 `EXT_UART_RX`) | ✗ |
| **로직 레벨** | **3.3 V** (5 V 직결 금지) | ✗ |
| **기본 속도** | **921600 bps** | ✅ `XM_SetExternalUartBaudrate()` (9600 ~ 921600) |
| **데이터 비트** | **8** | ✗ |
| **패리티** | **없음 (None)** | ✗ |
| **스톱 비트** | **1** | ✗ |
| **흐름 제어** | **없음** — RTS/CTS 선 안 씁니다 | ✗ |
| 한 번에 보낼 수 있는 양 | **128 바이트** (`XM_EXT_UART_TX_MAX_BYTES`) | ✗ |

**요약하면 `921600 8N1, 흐름제어 없음`** 입니다. 터미널 프로그램이나 상대 MCU 를 이대로 설정하세요.
속도만 양쪽을 똑같이 바꿀 수 있고, **8N1 은 펌웨어에서 바꿀 수단이 없습니다**.

<details>
<summary>내부 구성 (깊이 디버깅할 때만 필요합니다)</summary>

| 항목 | 값 |
|---|---|
| GPIO | Alternate Function Push-Pull, **풀업/풀다운 없음**, Speed LOW, `AF7_USART2` |
| 수신 방식 | **DMA + IDLE 라인 검출** — 상대가 한 덩이 보내고 선이 조용해지면 그때 콜백 |
| RX DMA | DMA1_Stream4, Circular, byte 단위, 우선순위 Very High |
| TX DMA | DMA2_Stream1, Normal, byte 단위, 우선순위 Low |
| 인터럽트 우선순위 | USART2 / RX DMA / TX DMA 모두 preempt **6** |
| 하드웨어 FIFO | 켜짐, TX·RX 임계값 1/4 |
| 오버샘플링 | 16 |
| 커널 클럭 | 120 MHz |
| 내부 버퍼 | RX DMA 256 B, TX DMA **128 B**(= 1 회 송신 상한) |

**풀업이 없다는 점**을 기억하세요. 상대 보드가 꺼져 있거나 선이 빠지면 RX 가 플로팅 상태가
되어 잡음을 데이터로 오인할 수 있습니다. `g_rx_bad_crc` 가 튀면 이 경우를 의심하세요.

</details>

### 🔌 쓸 수 있는 함수

| 함수 | 하는 일 |
|---|---|
| `XM_SetExternalUartBaudrate(XM_UART_BAUD_115200)` | 통신 속도 설정 |
| `XM_AttachExternalUart(콜백)` | 수신 시작 (`Control_Setup()` 에서 1회) |
| `XM_SendExternalUartData(buf, len)` | 보내기 — **기다리지 않음** |
| `XM_SendExternalUartDataBlocking(buf, len)` | 보내기 — 완료까지 대기, **`Control_Setup()` 전용** |
| `XM_EnsureExternalUartRxArmed()` | 수신이 멈췄으면 되살림 (100ms 주기 권장) |

## 3️⃣ 사전 지식 — 시작 전 알아둘 것

### 배선이 이 예제의 절반입니다

```
   보드 A                            보드 B
   ┌──────────┐                     ┌──────────┐
   │ PD5 (TX) ├────────────────────►│ PD6 (RX) │
   │ PD6 (RX) │◄────────────────────┤ PD5 (TX) │
   │ GND      ├─────────────────────┤ GND      │
   └──────────┘                     └──────────┘
```

- **TX 와 RX 를 교차**해야 합니다. TX-TX 로 이으면 아무것도 오지 않습니다.
- **GND 를 반드시 이으세요.** 안 하면 통신이 됐다 안 됐다 합니다.
- **3.3V 로직입니다.** 5V 장비를 직결하면 MCU 가 손상됩니다 — 레벨 시프터를 쓰세요.

### 시리얼은 "메시지" 가 아니라 "바이트 흐름" 입니다

보내는 쪽이 5바이트를 한 번에 보내도, 받는 쪽에서 **한 번에 5바이트로 도착한다는
보장이 없습니다.** 2바이트 + 3바이트로 쪼개져 올 수도 있고, 다음 메시지가 붙어서
8바이트로 올 수도 있습니다.

그래서 받는 쪽은 **"메시지가 여기서 시작한다"는 표시(헤더)를 찾아가며 조립**해야
합니다. 이 예제의 `DrainAndParse()` 가 그 일을 합니다 — 시리얼 통신을 처음 짜는
분들이 가장 많이 빠뜨리는 부분입니다.

## 4️⃣ 핵심 코드 — 무엇이 어디서 일어나나

### 프레임 형식 (이 예제가 임의로 정한 것)

```
+------+------+---------+---------+----------+
| 0xA5 | 0x5A | seq(hi) | seq(lo) | checksum |   = 5 bytes
+------+------+---------+---------+----------+
  헤더 2바이트       16비트 카운터      앞 4바이트 XOR
```

XM10 이 강제하는 형식이 아닙니다. 여러분의 장비 형식에 맞게 바꾸세요.

### 수신 콜백 — 복사만 하고 즉시 빠져나옵니다

```c
static void OnSerialRx(const uint8_t* data, uint32_t len)
{
    /* 링버퍼에 복사만! 해석은 Control_Loop() 에서 */
}
```

> ⚠️ **여기서 오래 걸리면 발바닥 센서(GRF)가 밀립니다.**
> 이 콜백은 XM10 내부의 **공유 수신 태스크**에서 실행되는데, 그 태스크는 GRF 의
> 1kHz 수신도 함께 처리합니다. 여기서 파싱·계산·대기를 하면 그만큼 GRF 데이터가
> 늦어집니다. **복사만 하세요.**

> ⚠️ **`data` 포인터는 콜백이 끝나면 무효입니다.** 내부 임시 버퍼를 가리키고 있어서,
> 저장해 뒀다가 나중에 읽으면 엉뚱한 값이 나옵니다. **내용을 복사**하세요.

### 송신이 `false` 를 돌려주는 건 에러가 아닙니다

```c
if (XM_SendExternalUartData(frame, FRAME_LEN)) {
    g_tx_count++;
} else {
    g_tx_busy++;   /* 직전 전송이 아직 안 끝났을 뿐 — 다음 주기에 다시 */
}
```

`XM_SendExternalUartData()` 는 **기다리지 않습니다.** 직전 전송이 진행 중이면 바로
`false` 를 돌려주고 끝냅니다. 1kHz 제어 루프에서 매 틱 불러도 루프가 멈추지 않습니다.

## 5️⃣ 실험 — 절차

1. `external_uart_pingpong.c` 를 `XM_Apps/Control_Task/control_task.c` 에 복사하고 빌드합니다.
2. **두 보드 모두**에 같은 펌웨어를 업로드합니다.
3. 위 3️⃣의 배선대로 PD5↔PD6 교차 + GND 를 연결합니다.
4. 디버거를 붙이고 Live Expressions 에 아래를 등록합니다.

| 변수 | 정상 | 이상하면 |
|---|---|---|
| `g_tx_count` | 초당 10씩 증가 | 0 → 코드가 안 돌고 있음 |
| `g_rx_bytes` | 계속 증가 | 0 → **배선부터** 확인 (교차·GND) |
| `g_rx_frame_ok` | 초당 10씩 증가 | 0 인데 `g_rx_bytes` 는 증가 → 속도 불일치 |
| `g_rx_bad_crc` | **0** | 0 아니면 → 속도 불일치, 접촉 불량, 노이즈 |
| `g_peer_seq` | 상대 보드 카운터와 같이 증가 | 안 변하면 → 상대가 안 보내는 중 |
| `g_rx_ring_drop` | **0** | 0 아니면 → `RX_RING_SIZE` 를 키우세요 |

5. 한쪽 보드의 전원을 뺐다 꽂아 보세요. `XM_EnsureExternalUartRxArmed()` 덕분에
   다시 연결하면 수신이 저절로 살아납니다.

---

## 6️⃣ 확장 아이디어 — 여기서 무엇을 더 할 수 있나

- **길이 필드를 넣어 가변 길이 메시지**를 주고받아 보세요 (헤더 + 길이 + 본문 + 체크섬).
- 128 바이트가 넘는 데이터를 **여러 번에 나눠 보내고** 받는 쪽에서 다시 합쳐 보세요.
- 센서값을 실어 보내 **한 보드가 측정하고 다른 보드가 제어**하게 만들어 보세요.
- 체크섬을 XOR 대신 **CRC16** 으로 바꿔 신뢰도를 높여 보세요.
- 상대를 PC 로 바꿔서 (USB-시리얼 어댑터) 파이썬 스크립트와 통신해 보세요.

## ❓ 흔한 실수

| 증상 | 원인 |
|---|---|
| 아무것도 안 옴 (`g_rx_bytes` = 0) | TX/RX 를 교차하지 않음 / GND 미연결 / 상대 보드 꺼짐 |
| `g_rx_bad_crc` 만 증가 | 두 보드의 통신 속도가 다름 |
| 콜백에서 받은 포인터를 저장했다가 나중에 읽음 | 콜백이 끝나면 그 메모리는 무효 — 반드시 복사 |
| 콜백 안에서 파싱·printf·대기 | 공유 수신 태스크를 붙잡아 GRF 수신이 밀림 |
| 128 바이트 넘게 한 번에 전송 시도 | 보내지 않고 `false` 반환 — 나눠 보내야 함 |
| 컴파일 에러 `XM_UART_BAUD_921600 undeclared` | External UART 를 Xsens IMU 가 쓰도록 설정된 빌드입니다. 관리자에게 문의하세요 |
