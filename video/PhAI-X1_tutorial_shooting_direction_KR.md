# 🎬 PhAI-X1 시작하기 튜토리얼 — 촬영 디렉션 (v2, 한국어)

> **이 영상이 누구를 위한 것인가**: PhAI-X1(H10 외골격 + XM10 보드)을 처음 받은 학생.
> **영상이 끝나면 시청자가 할 수 있는 것**: ① 내 손으로 보드에 코드를 올려 **로봇을 움직이고**, ② **PhAI Studio**로 그 데이터를 실시간으로 본다. (그다음 편에서 EMG 센서로 직접 제어)
> **촬영 기준**: **Rev 2.0 보드 전용**, 펌웨어는 **XM-Dev 최신 버전** 기준. ST-Link + STM32CubeIDE로 직접 올리는 방식.
> **톤**: 친절하게. 전문용어는 한 번씩 쉽게 풀어주고, "여기서 막혀도 괜찮아요"라는 안심을 준다.

## 0. 큰 그림 (촬영 담당용 요약)

이 영상은 "맨손에서 → 로봇이 움직이고 → 데이터가 보이는" 데까지 한 번에 보여줍니다. 세 개의 작은 성공(Hello World)으로 나뉩니다.

| 순서 | 보여줄 성공 | 한 줄 설명 |
|---|---|---|
| **성공 1 — 구동** | 로봇 다리가 스스로 ±25° 왕복 | 예제 코드를 올리고, 슈트 버튼을 누르면 로봇이 움직인다 |
| **성공 2 — 데이터** | 그 움직임이 PhAI Studio 그래프로 | USB로 연결하면 보드가 보내는 데이터가 실시간 그래프로 보인다 |
| **(다음 편) EMG** | 근육 신호로 제어 | 별도 영상. 이번 편은 여기까지의 "기초 닦기" |

**러닝타임 ≈ 14~16분.** 챕터 타임라인:
```
00:00  인트로 — PhAI-X1이 뭐예요?
00:45  ① 하드웨어 연결하기
03:00  ② 개발 환경 준비하기 (프로그램 설치 + SDK 받기)
06:00  ③ 예제 코드 가져오기 (Passive Mode)
08:30  ④ 빌드하고 보드에 올리기
10:30  ⑤ 로봇 깨우기 — 슈트 버튼 누르면 움직인다 ★클라이맥스
12:30  ⑥ PhAI Studio로 데이터 보기
14:30  ⑦ 안전 이야기 + 다음 편(EMG) 예고
```

> 💡 촬영 팁: **PC 화면 녹화**(CubeIDE/스튜디오)와 **실물 카메라**(보드·LED·로봇)를 둘 다 준비하세요. 편집에서 번갈아 보여줍니다. 각 표의 "카메라" 칸에서 [화]=화면 녹화, [실]=실물 카메라.

- PhAI Studio (데이터 모니터링용)

### ④ 예제 코드 가져오기 — Passive Mode (약 2분 30초)
> 친절 포인트: "코드를 처음부터 짤 필요 없어요. 예제를 그대로 가져다 쓰는 거예요."

XM10에서 **내가 코드를 쓰는 곳은 `XM_Apps/Control_Task/` 폴더 하나**입니다. 여기에 예제를 가져오는 방법은 두 가지 — 둘 다 보여주세요.

**방법 1 — 내용 덮어쓰기 (가장 간단, 추천)**
| 씬 | 카메라 | 화면 | 나레이션 |
|---|---|---|---|
| 4-1a | [화] | `examples/11_Passive_Mode/passive_mode.c` 열기 → 전체 선택(Ctrl+A) → 복사 → `Control_Task/control_task.c` 열어서 전체 붙여넣기(덮어쓰기) | "예제 내용을 통째로 복사해서, 원래 있던 control_task.c 안에 그대로 붙여넣어요. 파일은 하나만 유지됩니다." |

**방법 2 — 파일째 복사 (이때 한 가지 주의!)**
| 씬 | 카메라 | 화면 | 나레이션 |
|---|---|---|---|
| 4-1b | [화] | `passive_mode.c` 파일을 `Control_Task/` 폴더로 복사 → 이제 `control_task.c`와 `passive_mode.c`가 **둘 다** 있음 | "파일을 복사하면 두 파일이 같이 있게 돼요. 그런데 둘 다 `Control_Setup`/`Control_Loop` 함수를 갖고 있어서, 그대로 빌드하면 '함수가 두 번 정의됐다'는 에러가 납니다." |
| 4-1c | [화] | 해결책 두 가지 보여주기: (a) `control_task.c` **삭제**, 또는 (b) `control_task.c` 우클릭 → Resource Configurations → **Exclude from Build** 체크 | "그래서 둘 중 하나만 빌드에 들어가게 해야 해요. 원래 control_task.c를 **지우거나**, 아니면 **빌드에서 제외**하면 됩니다. 지우기 부담스러우면 제외를 추천해요 — 나중에 되돌리기 쉬우니까요." |

> 자막 카드(10초): **"중복 함수 에러가 나면? → control_task.c를 삭제하거나 빌드에서 제외!"**

## 3. 촬영 시 자주 막히는 곳 & 대비

| 증상 | 원인 | 현장 대응 |
|---|---|---|
| 보드 LED 안 켜짐 | 케이블 덜 꽂힘 / H10 전원 OFF | 재삽입 → H10 전원 확인 |
| "No ST-Link detected" | USB 허브/케이블 | PC 뒤쪽에 직접 |
| 빌드 중복 함수 에러 | control_task.c와 예제 .c 둘 다 있음 | control_task.c 삭제 또는 빌드 제외(④ 참고) |
| 슈트 버튼 눌렀는데 안 움직임 | ASSIST 모드 미진입 / 연결 대기 | 슈트 ASSIST 다시, CM 연결 LED 확인 |
| 로봇이 0도에서 멈춰 안 움직임(드물게) | Homing 완료 신호 누락 | XM-Dev 최신은 3초 뒤 자동 진행(패치 포함). 그래도 멈추면 슈트 STANDBY→ASSIST 또는 전원 리셋 |
| PhAI Studio에 데이터 안 뜸 | Connect 안 누름 / 포트 다른 프로그램 점유 | 스튜디오에서 포트 선택 후 Connect, 다른 시리얼 앱 종료 |

> 📌 **리허설 1회 필수**: 본 촬영 전에 ②~⑦을 한 번 끝까지 돌려보세요. 특히 ⑥(슈트 ASSIST → 왕복)을 2~3회 확인.
